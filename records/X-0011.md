## 关键判断（四条）

### 一、「能不能装 `F:\zxc` 下」→ **能，且本来就该装那儿**

`F:\zxc` 是本机**既有的工具安装根**（实测：`F:\zxc\UE_5.8`、`F:\zxc\Microsoft Visual Studio`、`F:\zxc\nodejs`、`F:\zxc\rust`、`F:\zxc\Git` 均在此）。两者的官方分发形态**都不绑定安装器**：

| 工具 | 官方形态 | 是否支持自定义目录 |
|---|---|---|
| **Go** | `go1.27.1.windows-amd64.zip`（免安装） | ✅ **开箱支持** —— 解压即用 |
| **Luban** | GitHub release `Luban.7z` | ✅ 解压即用（**自带 `Luban.exe`**） |

> **故不采用 `winget install GoLang.Go`** —— 那个路径会把 Go 装进 `C:\Program Files\Go`，且无法改。**zip 直装才满足「装 F 盘」**。

### 二、版本取值

| 工具 | 取值 | 依据 |

| **Go** | **1.27.1** | 官网 `dl/?mode=json` 的**最新稳定版**（次新 1.26.8）；满足台账「建议 ≥ 1.24」 |
| **Luban** | **v5.1.0** | GitHub **latest release**（2026-09-10 发布） |

## 安装与验证

### 1. Go —— 下载校验 + 编译冒烟

```bash
# sha256 与官网 dl/?mode=json 公布值比对
$ sha256sum go1.27.1.windows-amd64.zip
a3911b5e0e1b1053f25ed0675f4c1c6aad1e2bfcf253df2b9be4caabd2edd95d   ← 与官方一致 ✅
# 大小 78,931,360 bytes（= 75.3 MB）与官方一致 ✅

# 解压 → F:\zxc\go ；配置环境变量后（模拟新终端）
$ go version
go version go1.27.1 windows/amd64

$ go env GOPATH GOMODCACHE GOBIN GOROOT
F:\zxc\gopath
F:\zxc\gopath\pkg\mod
F:\zxc\gopath\bin
F:\zxc\go

# ★ 真实编译（不只 --version —— 台账纪律②「装了 ≠ 能用」）
$ go build -o gotest.exe .   → build: OK
$ ./gotest.exe               → SmokeTest OK on windows amd64 go1.27.1
$ go vet .                   → vet: OK
```

### 2. Luban —— **端到端导表**

用官方 `luban_examples` 的 `DataTables`（138 个文件）作输入：

```bash
$ Luban.exe -t all -c go-json -d json \
    --conf .../DataTables/luban.conf \
    -x outputCodeDir=.../out/gen \
    -x outputDataDir=.../out/data \
    -x lubanGoModule=demo/luban
...
INFO|process code target:"go-json" end
INFO|bye~
# 退出码 0 ✅

# 产出规模
Go 代码文件: 207
JSON 数据文件: 53
```

### 3. **联调验证** —— Luban 生成的 Go 代码能否编译（**最有价值的一条**）

```bash
$ cd out && printf 'module demo/luban\n\ngo 1.27\n' > go.mod
$ go build ./...   → 退出码 0 ✅
$ go vet ./...     → 无输出（通过）✅
```

> **结论**：**「Luban 导表 → Go 编译」这条链路端到端跑通** —— 不只是两个工具各自「能跑」，而是**它们串起来能用**。
> 生成代码包名 `cfg`（`Tables.go` → `package cfg`），与官方示例 `main.go` 的 `cfg.NewTables(...)` 一致。

**Luban 完整命令模板**（供 M1 建表时复用）：

```
<Luban.exe> -t <target> -c <codeTarget> -d <dataTarget> --conf <luban.conf>
            -x outputCodeDir=<生成代码目录> -x outputDataDir=<生成数据目录>
            -x lubanGoModule=<go module 路径>
```
> 本项目预期取值：`-t server`/`client`（conf 里已定义 groups）、`-c go-json`（服务端）+ **另跑一次 C++**（客户端）。
