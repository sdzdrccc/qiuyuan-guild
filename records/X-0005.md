## 关键判断（三条，都不是照着字面答）

### 一、这是**真缺口**，不是「讲一遍常识」

方案 §3.2 把 `ue-client/` 画成**一行**「UE5 客户端」，止于一级目录。
而 `ROADMAP.md` §2 的 **M1 第一件事就是建骨架** —— 缺口会在开工第一小时撞上。故新建 `docs/PROJECT-STRUCTURE.md` 作为施工图。

### 二、「预留手机端」这句话**有歧义**，必须先解歧

`ROADMAP.md` §2 的 M1 **Out of scope 明写「❌ 移动端适配」**。所以「预留」**不能**被读成「现在做适配」。

> **解歧为**：**只做「零成本且事后不可补」的事**（勾 Mobile 平台 / 输入抽象 / 资产按移动端预算 / 保留无损源）；
> **不做**要投人排期、且事后可补的事（竖屏布局 / DeviceProfile / ASTC / 打包流水线）。
> **判据**：「不做」将来会**推翻已写的东西** → 现在做；将来只是**补配置 / 补布局** → 现在不做。

### 三、动笔前先探测环境 —— **结果抓出一个真阻塞**

原以为问题只是「怎么建」，实测后发现**当前环境建了也编译不过**（见下）。

### 🔴 阻塞详情：MSVC `14.44.35207` 被 UE 5.8 明确禁用

UE 5.8 的 `Engine/Config/Windows/Windows_SDK.json`：

```json
"BannedVisualCppVersions": [
    "14.50.0-14.50.35722",
    "14.44.0-14.44.35210",        ← 本机 14.44.35207 正落此区间
    "14.40.0-14.43.99999",
    "14.39.0-14.39.99999"
]
```

**原因**（同文件注释）：该版本有 **Template compile error**，**由 `14.44.35211` 修复**。

**本机 VS 补丁号已是 `17.14.39`，但 MSVC *工具链* 组件仍停在 `35207`** —— 两者**独立更新**。

**处置**：VS Installer → 修改 → 单个组件 → 更新 **MSVC v143 生成工具** 至 **≥ 14.44.35211**。

### 探测过程中的第二个教训

`vswhere -latest -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64` **返回空** —— 看似没装 C++。
但 `cl.exe` **实际存在于** `…/BuildTools/VC/Tools/MSVC/14.44.35207/bin/Hostx64/x64/cl.exe`。

> **组件 ID 查询不可靠 —— 要落到文件实测。**

## 关键取舍

| 取舍 | 结论 | 理由 |
|---|---|---|
| **Quality Preset** | **Scalable**（**推导建议，可复核**） | Epic 官方指引「Maximum → PC／主机，Scalable → 移动设备」。取 Scalable **不损失任何 PC 能力**（只是默认值更保守，PC 画质可在 `DeviceProfile` 单独开回）。**反方留痕**：若把上游「原型期全画质」理解为「UE5 工程也须 PC 优先」，则取 Maximum —— 此时**须在 M1 就登记「移动端改造清单」** |
| **M1 是否拆模块** | **不拆**（单模块） | 拆模块是**平级加目录 + 改两处构建文件**，成本低、**故不必预拆**；等 `world/combat/ui` 三条线**真实**撞上编译时间或耦合问题再拆（方案 §10 反模式：过早优化） |
| **Quality Preset 之外的「预留」** | 只勾 Mobile + 三条纪律 | 其余（竖屏 UI / DeviceProfile / ASTC / 打包）**全部后补** —— M1 out of scope |
| **上游 §4.3 渲染管线改造清单** | **不抄进施工图** | 那是「做移动端时」的执行依据，**不是 M1 的**。抄进来只会让 M1 范围膨胀（违反范围闸门） |
