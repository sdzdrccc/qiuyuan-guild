## 关键判断（六条）

### 一、「项目开始之前必有的功能」= 环境是可验证的地基

大人这句定性很准 —— **环境不是备忘，是地基**，且它**可验证**。三条理由：

| 理由 | 说明 |
|---|---|
| **错一次要重装** | 编译器 / SDK 版本不对 → 装机成本重复支付 |
| **缺一项要停工** | 工具链缺 Go / protoc / Luban → M1 的账号服、协议、配表**全写不了** |
| **事后返工远贵于开工前对齐** | 同「移动端资产预算」的逻辑：**规格前置**（上游 §5.5） |

**与已有纪律同源**：上游 §5.5 说「最贵的错误不是做得不好，而是**做了 500 个资产之后发现规格不对**」——
环境是**同一个道理的更底层版**：**写了 500 行代码之后发现编译不了。**

### 三、资产命名**看似冲突，实为场合切分**（ADR-0013）

关 `X-0005` 遗留的「`CONVENTIONS.md` §6.1 应补录 UE 资产前缀」时，发现两条既有约定**看似打架**：

| 来源 | 规范 | 例 |
|---|---|---|
| 上游《技术架构》**§5.4** | kebab + 类别前缀 | `building-roof-xieshan-01-side.fbx` |
| `PROJECT-STRUCTURE.md` §4（Epic） | 前缀_PascalCase | `SM_Roof_Xieshan_01` |

**关键判断：不是二选一。** 判据是「**引擎内 vs 引擎外**」——

- **引擎内**（`Content/` 的 `.uasset`）→ **Epic 前缀**。因为资产名**受引擎约束**（C++ 类名、重定向器、蓝图引用）。
- **引擎外**（源文件 / 生成图 / AI 批量产物 / 交付包）→ **上游 §5.4 kebab**。因为它是**生产管线**产物，要能被脚本批量回溯与重生成。

**与 ADR-0002 不冲突的原因**：ADR-0002 的「需求 > 契约 > 原型」**前提是两者管同一件事**。此处**管的不是同一件事**，故不构成层级冲突。

> **这个判断是「推导」不是「裁决」**（留痕 · 可复核）：依「该场合的法定形式是什么就用什么」（`CONVENTIONS.md` §6.1 原判据）推得。

### 六、门禁**真的联动了** —— 并暴露 R6 判据过粗

dalu 落 `data/.gitkeep` 骨架后，**guild 的 R6 立刻报错**：

```
✗ R6  配置表目录存在但**无任何配置文件** —— 建了目录未放内容（禁止空集真空通过）
→ 结果：不通过（1 错 / 1 警告）
```

**这是好事**：证明门禁**确实在跨仓联动**（`check-data.js` 会自动探测 `qiuyuan-dalu/data`）。
**但判据过粗**：它把「**骨架期**」（目录只有 `.gitkeep`，尚未到放表的时候）与「**建了目录未放内容**」当成了一回事。

| 状态 | 应有判定 |
|---|---|
| 目录不存在 | 跳过（原逻辑已有） |
| **目录只有占位文件** | ✅ **骨架期 → 跳过**（**本轮新增**） |
| 目录有非占位文件、却无配置表 | ❌ 报错（原意，「禁止空集真空通过」） |
| 有配置表但命名不合规 | ❌ 报错（原意） |

**同时发现 R6 此前没有反向测试**（违反 `CONVENTIONS.md` §7.1 **纪律 2**：「每条规则必须有反向测试」）。
**一并补齐**：`--self-test` 由 **27 → 33 用例**（新增 6 条，含「仅 `.gitkeep` 不得报错」与「有内容无配置表必报错」两侧）。

> **可迁移判据**：**「反空集真空通过」的对象是「该有内容却没有」，不是「还没到该有内容的时候」。**
> 两者在文件系统上长得一样（都是「没有配置文件」），**必须靠旁证区分** —— 这里用的旁证是「**是否有非占位文件**」。
> 与坑 9（语义判断别硬写成脚本）、坑 3（空集真空通过）同族。

**现象**：`git push` 报 `Post "https://lfs.github.com/.../locks/verify": proxyconnect tcp: dial tcp 127.0.0.1:7890: ... actively refused it` → `failed to push`。

**根因（两条通道不一致）**：

| 通道 | 走什么 | 受影响？ |
|---|---|---|
| **git 数据传输** | remote 是 **SSH**（`git@github.com:...`） | ❌ 不吃 `http.proxy` |
| **Git LFS 对象 / 锁 API** | **HTTPS**（`https://github.com/.../info/lfs`） | ✅ **吃 `http.proxy`** |

全局配了 `http.proxy = http://127.0.0.1:7890`，而**代理当时没开** → git 走 SSH 正常，**LFS 走 HTTPS 撞死代理** → 整个 push 被 pre-push hook 拦下。

**实测**：`curl -x http://127.0.0.1:7890 https://github.com` → `000`（不通）；`curl https://github.com` → **`200`（直连通）**。

**处置（仅本仓，不动全局配置）**：

```bash
git config --local "lfs.https://github.com/sdzdrccc/qiuyuan-dalu.git/info/lfs.locksverify" false
git config --local "http.https://github.com/.proxy" ""     # 让 GitHub 走直连（实测直连可达）
```

> **可迁移判据**：**「git 走 SSH」不代表「LFS 也走 SSH」。** LFS 只走 HTTPS —— 配了代理时，**两条通道要分别验证**。
> 与坑 12/16 同源：**「这一层通了」≠「那一层也通了」**。
