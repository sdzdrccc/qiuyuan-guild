## 三、八条的落地要点

### S1 · 复审与销号（**价值最高**）

**缺口实证**：五步流程覆盖「审 → 产记录」，**没有一步说「修完之后怎么办」**。
`X-0015` 状态长期停在 `待验收`，而 dalu 已修 6 处、门禁已转绿 —— 实际靠「**又开一篇 `X-0016`**」承担，属**流程外自发**。

**销号三条件**（缺一不可）：① **逐条复跑原证据**（不是「对方说修了」）；② **门禁转绿**（或写明为何该红）；③ **只追加**（销号写新记录，不改原记录）。
**部分转绿** → 分别列「已销 / 未销」，**不许笼统写「已修复」**；ledger `待验收 → 已关闭`。

### S2 · 两个「纪元」不是一回事 → 门禁 `C7`

| 概念 | 在哪 | 谁能改 |
|---|---|---|
| **门禁基线 `GATE_EPOCH`** | 脚本内 · 单一值 | **只增不改** —— 移动须**落记录 + 大人裁**；回拨 = **洗白存量** |
| **审阅快照** | 记录头部 | 每次审阅各写一份，**只标识范围，不参与门禁判定** |

> **实测风险**：`REVIEW-PROCESS` 第 1 步原写「记下**门禁纪元**」，而脚本里是**单一基线** —— 二者被混为一谈。
> 且「只增不改」原本**只活在代码注释里**，真源文档没有。
> → **`C7` 三条判据**：可解析 → 是 HEAD 的祖先 → **历史值都是当前值的祖先**（回拨即 err）。

### S3 · 独立复算 ≠ 复跑

**复跑**抓「环境不对」；**独立复算**才抓「**对方的脚本本身错**」。
**实证**：本项目数值上正栽过一次（`v0.5` 自称期望恰 `1.0000`，实测 `1.162`），**只有另写一遍才能发现**。
**判读法**：口径 / RNG 不同 ⇒ **只验统计量**（期望 / 区间 / 单调 / 越界），**不逐位对齐**。

★ **配套纪律（§5 纪律 4）**：**审阅者自写的工具同样受门禁约束**，**冲突时先怀疑自己**。
**实证**：审阅 `X-0015` 时，审阅者的临时脚本把 **3 笔合规提交误判为违规**（漏了「同批记录」判定），**门禁是对的**。

### S4 · 反事实复验

**凡宣称「修好了某类环境问题」，须在该问题的恶劣条件下复跑** ——
编码（敌对 `--default-character-set`）· 大小写敏感 · CRLF · 并发。
**没在恶劣条件下跑过的修法，只是「当前环境恰好没坏」。**
**实证**：证明「修中文乱码」是根因修复，靠的是**用 gbk 删库重建**后注释 HEX 逐字节不变。

### S5 · 「本次未覆盖」必填 → 门禁 `C8`

`X-0015` 那次**没审** `ue-client/` 的 C++、`admin/`、UE-MCP 链路，**却一处都没写明** ⇒ 读者会把「审过一部分」读成「全审过」。
**`C8`**：审阅类记录（大标题形如 `<对象> 审阅 —— …`）须有该节；**认节，不认正文里出现「未覆盖」四字**（防假通过）。
**只对审阅类记录生效** —— `审阅流程化` / `审阅模板补节` 这类**流程建设**记录不适用（实测：首版判据曾把 `X-0016` / `X-0017` 误判）。

### S6 · 文档 ↔ 门禁锚定 → 新脚本 `D1`~`D4`

**缺口实证**：`REVIEW-PROCESS.md` 自述与 `CONVENTIONS.md` / `AGENTS.md` **同级**，却**没有任何门禁引用它**（实查 grep 为空）。
→ 它长出**三个已在腐烂的接口**：脚本清单 / 规则 ID 范围 / 仓外 skill 版本。

### ★ 第 5 处的依据（**独立推理 ≠ 复跑** —— 正是本记录 §`S3` 纪律的实践）

**代码事实**：`epochSet(ep)` = `git rev-list ep` = **ep 及其之前**的全部提交（= 「存量」豁免区）；
`fileIsFresh` 判「文件**首次出现**的提交**不在** `epochSet` 里」→ 即提交在纪元**之后** → 才须办。

⇒ **推进**纪元（改到**更新**的提交）= 豁免区**变大** = **洗白存量**；
⇒ **回拨**纪元（改到**更早**的提交）= 豁免区**变小** = **变严**（存量转新增）。

**本记录内部本就自相矛盾**：§三-`S2` 两纪元表写「**回拨** = 存量被洗白」，
而**紧接其后的**判据段写「为了让自己这次干净而**推进** `GATE_EPOCH` = **洗白存量**」——
**两句相反，后者才对**。`C7` 首版实现按**前者**写（`isAncestor(old, cur)` ⇒ 只拦回拨），
于是**恰好放过了真正危险的方向** —— 正落进本记录 §`S5` 引的纪律 2「**脚本假装能判 = 虚假的安心**」。

**已修正为** `epochMove()` 三态：**推进 ⇒ `err`**（洗白）· **回拨 ⇒ `warn`**（变严，须落记录 + 大人裁）· **无祖先关系 ⇒ `err`**（历史被改写）。
`REVIEW-PROCESS` §3-1 表与 §5-3 同步改口径；版本 **v1.2 → v1.3**（**内容零变更**，仅口径纠反 + 标题计数）。
