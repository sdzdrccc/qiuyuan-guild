## 0. 本契约已钉死的两处不一致（重要）

原型里存在**两处自相矛盾**，本契约取**有代码证据**的一方为准，并记为勘误。
> ⚠️ **v0.2 注**：按 ADR-0002，原型只是**参考实作**。下列两条之所以能「取代码证据为准」，是因为代码证据**恰好与需求层一致**；若二者不一致，**一律以需求层为准**。

### 勘误一：灵根枚举的 5/6/7 顺序

| 说法 | 出处 | 判定 |
|---|---|---|
| `0~7 = 金木水火土风雷冰` | `WorldviewData.ROOT_NAMES`、`CharacterRoot.java`、`SpiritualRoot.cs`、`AttributesCalculator`（mainRoot==5 风系 / ==6 雷系 / ==7 冰系）、`CombatService`（atkRoot==6 雷系破法） | ✅ **权威** |
| `0~7 = 金木水火土雷风冰` | 原型 `docs/03-protocol-and-api.md` 第 113 行 | ❌ **笔误，作废** |

> **证据链**：6 处代码一致（含战斗结算里的硬逻辑），仅 1 处文档不同 → 判文档为笔误。
> 本条**必须**按 `CONVENTIONS.md` §1.1 铁律 2 的体例处理：原型侧更正时**只追加勘误，不改历史**。

### 勘误二：境界索引的上界（**原型内部**的矛盾）

| 说法 | 出处 | 判定 |
|---|---|---|
| **9 大境界**，索引 `0~8` = 炼气 / 筑基 / 金丹 / 元婴 / 化神 / 炼虚 / 合体 / 大乘 / 渡劫；原型口径共 **42 阶段** | `RealmAttrCatalog.REALM_NAMES` + `REALM_LEVELS = {10,4,4,4,4,4,4,4,4}`（含单测逐阶段校验） | ✅ **原型内部权威** |

> 「造化」不在 9 境界之内 —— 该注释是旧版残留。
> ⚠️ **本勘误只解决「原型内部两说谁对」**，**不决定契约口径**。契约的粒度已由 **ADR-0004 裁定为 9 层**（原型 42 阶段作废），见 §4。

## 0.2 物理映射**不在本契约内**（v0.2 新增 · ADR-0001）

**契约管「逻辑模型」，物理映射归下游（`qiuyuan-dalu`）。**

| 层 | 内容 | 谁定 | 变更 |
|---|---|---|---|
| **逻辑模型**（**本契约**） | 实体、字段语义、类型、取值范围、约束、枚举、公式 | guild | 改需 ADR，低频 |
| **物理映射**（**不在本契约**） | 表名 / 前缀 / 主键命名 / 存储引擎 / 字符集 / 分片键 / 索引 / ORM | `qiuyuan-dalu` | 工程侧自决，**可整体替换** |

**三条硬规则**：

1. **本契约里不出现表名。** 陈述「实体 `角色`」，不陈述「表 `xx_characters`」。
2. **换数据库不构成契约变更。** MySQL → PostgreSQL、改前缀、改分片键 —— 本契约**一字不动**。
   反之，若某次「换库」逼得本契约要改，说明**物理细节漏进了契约**，是违规信号。
3. **判据**：**把本契约交给一个完全不知道表名的人，他应能设计出任意一套表结构并实现它。**

> **⚠️ 原型表名的地位（v0.2 降级）**：`xx_` 前缀是**原型作者的占位约定**，**不是需求、不是规范**。
> 需求层（`10-MMO化/技术架构与技术选型.md` §3.4）的表名是 **`account` / `role` / `role_attribute` / `role_cultivation` / …（无前缀）**，主键 **`role_id`**，并已为 `role_id` 哈希分片预留。
> 本契约按 ADR-0002 **对齐需求层命名**，并对 `xx_` 前缀做**引用性记载**（说明原型曾用，仅备查，**不构成约束**）。
>
> **唯一进入契约的「物理性」要求**：**玩家表以 `role_id` 为一级键，须可哈希分片** —— 这是需求层的**架构约束**（`技术架构与技术选型.md` §3.4），不是实现细节。

## 2. 通用约定

1. **实体命名**：**语义清晰、不缩写**，英文实体名用**单数 PascalCase**（`Role` / `RoleRoot`）。
   下游可自行决定表名与前后缀 —— **本契约不规定**（ADR-0001）。
2. **注释强制**：每实体必须有说明，每字段必须有字段说明（含义 + 取值范围 / 枚举）。
   > 落到物理层时，**必须**转成表注释与字段注释（`CONVENTIONS.md` §3.2）。
3. **枚举必须留 `unknown`**：凡向后回填的枚举，必须允许「未核实」取值。
4. **定义型 vs 实例型**：
   - **定义型**（`*Def` / `*Config`）= 策划配置，全服共用，可热改
   - **实例型**（`RoleItem` / `WorldDrop` / `Storage*`）= 玩家资产，逐件独立
   - **判据**：能被同一个玩家持有多份且各自不同 → 实例型。
5. **属性「上限」不落库**：**上限**派生、**当前值**落库 —— 见 §6（ADR-0005 已裁定）。
6. **玩家数据以 `role_id` 为一级键**：须可哈希分片（架构约束，来源 `10-MMO化/技术架构与技术选型.md` §3.4）。**这是唯一进入契约的物理性要求。**

## 3. 角色与成长

### 3.1 角色 `Role`（角色主实体）　·　**M1**

> **命名对齐（ADR-0002）**：原型用 `id` / `player_id` / `realm_index` / `realm_level`；需求层用 `role_id` / `account_id` / `realm_id` / `layer`。
> **本契约取需求层**。原型名仅备查，不构成约束。

| 字段 | 类型 | 语义 | 取值 |
|---|---|---|---|
| `role_id` | BIGINT | **角色主键**（一级键，须可分片） | — |
| `account_id` | BIGINT | 所属账号 | → `Account.account_id` |
| `name` | VARCHAR | 角色名（名号） | — |
| `gender` | INT | 性别 | `0=男, 1=女` |
| `realm_id` | INT | **大境界** | **`1~9`**（`0` = 凡人，见 §4）—— ADR-0006 |
| `layer` | INT | 境界内层次 | **`1~9`**（第 9 层 = 圆满）；炼气恒 **`1~10`** —— ADR-0004 |
| `exp` | DOUBLE | 修为值（突破用） | 上限 = 境界配置 `exp_max` |
| `mp` | DOUBLE | 灵力（施法资源） | 上限 = 境界配置 `mp_max`。**与 `exp` 分离** |
| `spiritual_root_quality` | INT | 资质品级 | `0~6` |
| `body_tier` | INT | 体质层级 | `0~3` = 后天凡体 / 先天灵体 / 顶级圣体 / 禁忌神体 |
| `body_name` | VARCHAR | 体质名称 | 如「金罡灵体」 |
| `xinmo` | DOUBLE | 心魔值 | `0~100` |
| `kuangzao` | DOUBLE | 狂躁值 | `0~100` |
| `dan_du` | DOUBLE | 丹毒值（炼艺反噬堆积） | `0~100` |
| `shenshi` | DOUBLE | 神识强度 | 影响术法 / 施法速度 / 突破小加成 / 炼艺成功率 |
| `hp` | DOUBLE | 当前生命 | 上限 = 境界配置 `hp_max` |
| `shield` | DOUBLE | 灵力护盾（法术效果） | 受击先扣盾 |
| `life_current` | DOUBLE | 剩余寿元（年） | 上限见 §4 寿元表 |
| `life_last_tick` | BIGINT | 上次寿元结算时间戳 | epoch ms，登录/查询时按现实时间扣减 |
| `created_at` | INSTANT | 创建时间 | — |

> **两条字段语义（易错，显式写死）**：
> - **`exp` ≠ `mp`** —— 修为（突破）与灵力（施法）是**两个独立资源**，历史上合并过一次又拆开。
> - **属性面板不落库** —— `hp_max` / 物攻法攻等**均不在本实体**，由 §6 实时派生（ADR-0005 已裁定：上限派生，须向上游提订正单）。
>
> **何谓「当前值」vs「上限值」**（**ADR-0005 已裁定**）：
> `hp` / `mp` / `shield` / `life_current` 是**状态**（✅ **落库**）→ 入本实体；
> `hp_max` / `mp_max` / 物攻 / 法攻 …是**派生**（❌ **不落库**）→ 见 §6。

### 3.2 角色灵根 `RoleRoot`（灵根明细）　·　**M1**

> 需求层把「灵根 / 品级 / 体质 / 道心 / 修为」合在 `role_cultivation` 一表；本契约**拆为独立实体**（更细的规范化），归属关系见 §1。

| 字段 | 类型 | 语义 | 取值 |
|---|---|---|---|
| `role_id` | BIGINT | → `Role.role_id` | — |
| `root_type` | INT | **灵根类型** | **`0~7` = 金木水火土风雷冰**（见勘误一） |
| `purity` | DOUBLE | 该灵根纯度 | `0~100` |
| `sort_order` | INT | 排序 | **`0` = 主灵根 = 纯度最高者** |

**关键语义**：

- **每根独立纯度**（不是角色一个总纯度）。
- **主灵根 = 纯度最高者**（`sort_order = 0`），不是建角时指定的。
- 灵根组合生成规则**按资质品级**：

| 品级 | 灵根构成 |

| `0` 五行杂伪灵根 | 4~5 个五行（不重复） |
| `1` 八系全杂灵根 | 全部 8 系 |
| `2` 变异杂灵根 | 1 变异（风/雷/冰，主） + 1~2 五行 |
| `3` 三灵根 | 3 个五行 |
| `4` 双灵根 | 2 个五行（主 + 副） |
| `5` 五行天灵根 | 1 个五行 |
| `6` 变异天灵根 | 1 个风 / 雷 / 冰 |

## 4. 境界体系（**权威定义**）

> **来源（v0.2 修正）**：需求层 `10-MMO化/境界体系` + `境界基础属性.md` §10.1 为主；原型 `RealmAttrCatalog` 为参考实作。

|---|---|---|---|

| 2 | 筑基 | 9 | `1–3` 初期 · `4–6` 中期 · `7–9` 后期；第 9 层 = **圆满** |
| 3 | 金丹 | 9 | 同上 |
| 4 | 元婴 | 9 | 同上 |
| 5 | 化神 | 9 | 同上 |
| 6 | 炼虚 | 9 | 同上 |
| 7 | 合体 | 9 | 同上 |
| 8 | 大乘 | 9 | 同上 |
| 9 | 渡劫 | 9 | 同上 |

**合计 82 台阶**（炼气 10 + 8 境 × 9）。

> **原型口径（4 阶段 / 42 台阶）已作废**，仅作历史备查。
> **判据**：原型的价值在**公式**，不在**表的行数** —— 行数由需求决定，公式只需换套用对象。

> ⚠️ **需求层自身仍有一处自相矛盾**（已登记待提订正）：`境界基础属性.md` §10.1 的 `level_index` 说明写「筑基及以上 `1–9`（**第 9 层 = 圆满**）」，同页脚注又写「阶段称谓由 **`1–3/4–6/7–9`** 层归段得出」—— 两处对第 9 层的归属不一致。
> **本契约取「第 9 层 = 圆满」**（与「大圆满」语义一致，且 `1–9` 共 9 层自洽）。

**凡人态（未入道）**：`realm_id = 0`，不落 `layer`，属性取「凡人基准值」，另存 `inductive_progress`（引气进度 `0~100`）；引气入体后转写 `realm_id = 1`、`layer = 1`。（来源：需求层 §10.1；ADR-0006）

**数值生成公式（权威）**：

> 公式的**指数与倍率框架**与粒度无关，可直接沿用；**套用对象 = 每「层」**（ADR-0004 裁定后确定）。

```
炼气 n 层   = 基准 × 1.18^(n-1)                    （n = 1~10）
筑基 1 层   = 基准 × 5
金丹 1 层   = 基准 × 5 × 3
其后每大境界 × 3

境内成长（筑基及以上，共 9 层）：
  原型的 4 阶段档位 ×1.25 / ×1.5625 / ×1.953125 已作废。
  新制须**等比覆盖同一总跨度**（第 1 层 → 第 9 层 = ×1.953125），
  即每次递增 ≈ ×1.0873（= 1.953125^(1/8)）。
  ⚠️ 精确倍率**待数值标定**后落定（约束：总跨度不变）—— 见 §10.2。
```

**基准值**：`HP=100 / MP=50 / ATK=10 / DEF=5`

**寿元表（按大境界）**：

### 6.1 来源 → 属性 投放表

| 来源 | 主要投放到 |
|---|---|
| 境界 + 小阶 | 全基础属性 |
| 体质层级 | 气血、物防、格挡、闪避（肉身系） |
| 资质品级 | 法攻、会心、会心伤害（天赋系） |
| **纯度（每根独立）** | 全部攻防 × 主根纯度效率；**副根纯度影响对应元素攻击** |
| **主灵根**（纯度最高者） | 对应元素攻击 **+20%**、对应元素抗性 **+10%**；决定突破 / 生克 / 废体判定 |
| 副灵根 | 对应元素攻击 **+5%**（多灵根；双灵根主 +25% 副 +10%） |
| **三负面** | 心魔 → 法术攻击/施法衰减；狂躁 → 会心波动；丹毒 → 全属性小幅衰减 |
| **生克** | 元素乘区（**不写入面板**，战斗时计算） |

### 6.2 纯度效率的边界（易错）

- 主根纯度 **`<30` → 废体惩罚 `-40%`**
- 主根纯度 **`>80` → 极品拉满**

### 6.3 战斗结算公式（**权威**）

```
命中判定: clamp((攻方命中 - 守方闪避) / 100, 5%, 95%)
会心判定: clamp(攻方会心 - 守方会心抗性, 2%, 60%)
格挡判定: clamp(守方格挡 - 攻方破防系数, 0%, 50%)

基础伤害（物理技能）：
  attack  = 物理攻击 × (1 + 攻方纯度效率)
  defense = 物理防御 × (1 - 攻方破防%) × (1 + 守方纯度效率)
  base    = max(1, attack - defense × 0.8)

基础伤害（法术技能）：同上，物攻/物防 → 法攻/法防

最终伤害 = base
  × 技能倍率
  × 元素乘区：攻方对应系攻击加成 × (1 - 守方对应系抗性) × 生克倍率
  × 会心乘区：命中会心 ? 会心伤害倍率（默认 1.5） : 1
  × 格挡乘区：触发格挡 ? (1 - 格挡减伤) : 1
  × 负面修正：心魔 → 法术 -5%~-15%；狂躁 → 会心伤害 -10%；丹毒 → 全伤害 -5%
  × 随机浮动 0.9~1.1

跨阶修正：大阶差距 ≥ 2 时，元素生克倍率衰减 50%
```

**生克规则**：五行相克 **±20%**；雷**破法 +15%**；冰克火 / 水 / 金。

### 6.4 平衡红线（原型踩坑记录，**契约级约束**）

| 项 | 上限 / 保底 |
|---|---|
| 破防 | **≤ 60%**（防御收益须保底，避免防御贬值） |
| 会心率 | **封顶 60%**；会抗与命中有下限保障 |
| 元素与基础攻击 | **分属不同乘区**，但总量控制（加法池 / 乘法池分离） |
| 三负面 | **不能只有惩罚** —— 须留双刃机制（如心魔 >70 时法术威力 +20% 但可能失控） |
