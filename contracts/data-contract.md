## 0. 本契约已钉死的两处不一致（重要）

原型里存在**两处自相矛盾**，本契约取**有代码证据**的一方为准，并记为勘误。
> ⚠️ **v0.2 注**：按 ADR-0002，原型只是**参考实作**。下列两条之所以能「取代码证据为准」，是因为代码证据**恰好与需求层一致**；若二者不一致，**一律以需求层为准**。

### 勘误一：灵根枚举的 5/6/7 顺序

| 说法 | 出处 | 判定 |
|---|---|---|
| `0~7 = 金木水火土风雷冰` | `WorldviewData.ROOT_NAMES`、`CharacterRoot.java`、`SpiritualRoot.cs`、`AttributesCalculator`（mainRoot==5 风系 / ==6 雷系 / ==7 冰系）、`CombatService`（atkRoot==6 雷系破法） | ✅ **权威** |
| `0~7 = 金木水火土雷风冰` | 原型 `docs/03-protocol-and-api.md` 第 113 行 | ❌ **笔误，作废** |

> **证据链**：6 处代码一致（含战斗结算里的硬逻辑），仅 1 处文档不同 → 判文档为笔误。
> 本条**必须**按 `CONVENTIONS.md` §1.1 铁律 2 的体例处理：原型侧更正时**只追加勘误，不改历史**。

### 勘误二：境界索引的上界（**原型内部**的矛盾）

| 说法 | 出处 | 判定 |
|---|---|---|
| **9 大境界**，索引 `0~8` = 炼气 / 筑基 / 金丹 / 元婴 / 化神 / 炼虚 / 合体 / 大乘 / 渡劫；原型口径共 **42 阶段** | `RealmAttrCatalog.REALM_NAMES` + `REALM_LEVELS = {10,4,4,4,4,4,4,4,4}`（含单测逐阶段校验） | ✅ **原型内部权威** |
| `realmIndex(0=炼气...26=造化)` | `GameCharacter.java` 字段注释 | ❌ **过时注释，作废** |

> 「造化」不在 9 境界之内 —— 该注释是旧版残留。
> ⚠️ **本勘误只解决「原型内部两说谁对」**，**不决定契约口径**。契约的粒度已由 **ADR-0004 裁定为 9 层**（原型 42 阶段作废），见 §4。

### ✅ 已裁定一：境界全套口径（ADR-0004 + ADR-0006 · 2026-09-28）

## 0.2 物理映射**不在本契约内**（v0.2 新增 · ADR-0001）

**契约管「逻辑模型」，物理映射归下游（`qiuyuan-dalu`）。**

| 层 | 内容 | 谁定 | 变更 |
|---|---|---|---|
| **逻辑模型**（**本契约**） | 实体、字段语义、类型、取值范围、约束、枚举、公式 | guild | 改需 ADR，低频 |
| **物理映射**（**不在本契约**） | 表名 / 前缀 / 主键命名 / 存储引擎 / 字符集 / 分片键 / 索引 / ORM | `qiuyuan-dalu` | 工程侧自决，**可整体替换** |

**三条硬规则**：

1. **本契约里不出现表名。** 陈述「实体 `角色`」，不陈述「表 `xx_characters`」。
2. **换数据库不构成契约变更。** MySQL → PostgreSQL、改前缀、改分片键 —— 本契约**一字不动**。
   反之，若某次「换库」逼得本契约要改，说明**物理细节漏进了契约**，是违规信号。
3. **判据**：**把本契约交给一个完全不知道表名的人，他应能设计出任意一套表结构并实现它。**

> **⚠️ 原型表名的地位（v0.2 降级）**：`xx_` 前缀是**原型作者的占位约定**，**不是需求、不是规范**。
> 需求层（`10-MMO化/技术架构与技术选型.md` §3.4）的表名是 **`account` / `role` / `role_attribute` / `role_cultivation` / …（无前缀）**，主键 **`role_id`**，并已为 `role_id` 哈希分片预留。
> 本契约按 ADR-0002 **对齐需求层命名**，并对 `xx_` 前缀做**引用性记载**（说明原型曾用，仅备查，**不构成约束**）。
>
> **唯一进入契约的「物理性」要求**：**玩家表以 `role_id` 为一级键，须可哈希分片** —— 这是需求层的**架构约束**（`技术架构与技术选型.md` §3.4），不是实现细节。

## 2. 通用约定

1. **实体命名**：**语义清晰、不缩写**，英文实体名用**单数 PascalCase**（`Role` / `RoleRoot`）。
   下游可自行决定表名与前后缀 —— **本契约不规定**（ADR-0001）。
2. **注释强制**：每实体必须有说明，每字段必须有字段说明（含义 + 取值范围 / 枚举）。
   > 落到物理层时，**必须**转成表注释与字段注释（`CONVENTIONS.md` §3.2）。
3. **枚举必须留 `unknown`**：凡向后回填的枚举，必须允许「未核实」取值。
4. **定义型 vs 实例型**：
   - **定义型**（`*Def` / `*Config`）= 策划配置，全服共用，可热改
   - **实例型**（`RoleItem` / `WorldDrop` / `Storage*`）= 玩家资产，逐件独立
   - **判据**：能被同一个玩家持有多份且各自不同 → 实例型。
5. **属性「上限」不落库**：**上限**派生、**当前值**落库 —— 见 §6（ADR-0005 已裁定）。
6. **玩家数据以 `role_id` 为一级键**：须可哈希分片（架构约束，来源 `10-MMO化/技术架构与技术选型.md` §3.4）。**这是唯一进入契约的物理性要求。**

### 3.0 账号 `Account`（平台账号层）　·　**M1**

> **登录标识 = 手机号**（裁定 **B** · 原话「单账号单角色 + 手机号注册」）。
> **`username` / `email` 两字段不存在于本契约** —— 原型有，**已废**。
> ⚠️ **M1 不接短信验证码** —— 手机号仅作**登录标识**，凭**密码**登录（验证码属运营侧，另行裁定）。

| 字段 | 类型 | 语义 | 取值 |
|---|---|---|---|
| `account_id` | BIGINT | **账号主键** | — |
| `phone` | VARCHAR | **手机号** —— **唯一登录标识** | 唯一；**格式归物理层**（E.164 或 11 位国内号，二者等价） |
| `password_hash` | VARCHAR | 密码哈希 | **不可逆、可验证**（算法与 cost 归物理层，如 bcrypt） |
| `status` | INT | 账号状态 | `0=正常, 1=封禁, 2=注销` |
| `created_at` | INSTANT | 创建时间 | — |
| `last_login_at` | INSTANT | 最后登录时间 | 可空 |

**关键语义**：

- ★ **`Account` : `Role` = 1 : 1**（裁定 **B**「单账号单角色」）。
  **这是逻辑约束，属契约；实现它的是唯一索引，属物理层**（ADR-0001/0002：**约束归契约，索引归下游**）。
  > 判据：**契约说「至多一个」，下游自己决定用唯一索引、外键还是应用层校验。**
- ★ **`phone` 是唯一登录标识** —— 没有第二把钥匙。**换手机号 = 换账号**（改绑属运营侧功能，M1 不做）。
- **密码不落明文** —— 契约只要求「可验证 + 不可逆」，**具体算法不进契约**（那是物理/安全层）。

### 3.2 角色灵根 `RoleRoot`（灵根明细）　·　**M1**

> 需求层把「灵根 / 品级 / 体质 / 道心 / 修为」合在 `role_cultivation` 一表；本契约**拆为独立实体**（更细的规范化），归属关系见 §1。

| 字段 | 类型 | 语义 | 取值 |
|---|---|---|---|
| `role_id` | BIGINT | → `Role.role_id` | — |
| `root_type` | INT | **灵根类型** | **`0~7` = 金木水火土风雷冰**（见勘误一） |
| `purity` | DOUBLE | 该灵根纯度 | **`1~100`**（均匀随机，**与品级无关** —— 裁定 G） |
| `sort_order` | INT | 排序 | **`0` = 主灵根 = 纯度最高者** |

**关键语义**：

- **每根独立纯度**（不是角色一个总纯度）。
- ★ **纯度与品级无关**（裁定 **G**）：品级只管「**有几根、哪几个系**」，**不约束纯度高低**。
  任何品级的每一根，都各自独立取 `Uniform{1..100}` —— **全随机，不加设定**。
  > 轴心 `50.5` 即该分布的**期望**（不是「刻度中点」，那是巧合）—— 见 §6.2。
- **主灵根 = 纯度最高者**（`sort_order = 0`），不是建角时指定的。
- **灵根组合生成规则按资质品级**（★ **编号按「神通 + 修炼」双单调重排** —— 裁定 **K**）：

| `quality` | 品级 | 灵根构成 | 档位（`grade_rank`） |
|---|---|---|---|
| `0` | **八系全杂** | 全部 8 系（3 变异 + 5 五行） | `0` 废体 |
| `1` | 普通五行杂伪 | 4~5 个五行（不重复） | `0` 废体 |
| `2` | 三灵根 | 3 个五行 | `1` 中品 |
| `3` | 双灵根 | 2 个五行（主 + 副） | `1` 中品 |
| `4` | 变异杂灵根 | 1 变异（风 / 雷 / 冰） + 1~2 五行 | `2` 优品 |

### 6.2 灵根两项的派生口径（**双因子** · v0.4 定稿）

> ★ **本节 v0.4 整段重写**（ADR-0019 ⑦）。原文只有两条纯度阈值（「`<30` 废体惩罚 `-40%`」「`>80` 极品拉满」），
> **两条均已作废** —— 档位改由**品级**决定（裁定 **M**）。
>
> **正式规格 = `qiuyuan-dalu/docs/SPIRIT-ROOT-FORMULA.md`**（该域**数值公式的唯一真源**）。
> 本节是它在**契约层**的口径；两者不一致时**以彼为准**。

**一句话**：`最终值 = 品级值 G × 纯度系数 c + 加法项`

**① 品级值 `G`** —— 由**灵根根数**算出（**不照搬世界观表**）

```
C     = n_wuxing + n_variant               灵根总数（杂度：越多越弱）
n_eff = n_wuxing + n_variant × v           灵根当量（v = 变异价值）
G     = ( anchor × n_eff / C² ) ^ p        品级值（双灵根恰为 1.000）
```

**② 纯度系数 `c`** —— **连续式**（不是档表）

```
c = 1 + influence × ( purity − 50.5 ) / 50.5        →  0.80 ~ 1.20
```

| 侧 | 取值基准 |
|---|---|
| **伤害侧（神通）** | **法术对应灵根**那条的纯度（**逐系**取 —— 裁定 **L**） |
| **修炼侧** | **主灵根**纯度 = `roots[0].purity`（裁定 **N**） |

> **`50.5` 的来历**：它不是「刻度中点」，是 `Uniform{1..100}` 的**期望** ——
> 纯度取该分布时，此点系数**恰为 `1.0`**，从而「全服平均 ≈ ×1.0」。
> ⚠️ **期望 ≠ 实测平均**：取样量是「主根 = 各根 `max`」，**右偏** ⇒ 实测纯度系数期望 `1.089`，
> 属**校准项**，用 `add_*` 加法项校正即可。

**③ 最终值** —— **先乘后加**

```
最终神通 = G × c_伤害 + add_damage_ppm      / 1000000
最终修炼 = G × c_修炼 + add_cultivation_ppm / 1000000
```

**参数全在 `GameConfig`**（§3.3 六个键）—— GM 改一个数即生效，**不动代码**。

**两条边界（易错，显式写死）**：

1. ★ **档位（废体 / 极品）由品级 `grade_rank` 决定，与纯度无关**（裁定 **M**）——
   原「主根纯度 `<30` → 废体惩罚 `-40%`」与「`>80` → 极品拉满」**两条阈值已废**。
2. ★ **无对应灵根时**（角色没有该系灵根，却施放该系法术）：**不可学、不可放** ——
   **准入禁止**（**ADR-0020**），**不是**结算系数。故本节公式**不覆盖该情形**（它在**准入层**已被拦掉）。
   依据（上游明文）：`10-MMO化/流派与技能.md` §四「**灵根专属法术只有对应属性灵根修士可修炼**」。
   **两条不受限**：① **「无属性」法术**（通用 10 个）**全灵根可学**；② **多灵根修士**可学多个属性的法术。

**主次判据（品级主导 · 裁定 N 的量化落点）**：

| 侧 | 最终值跨度 | 纯度跨度 | 判据（品级 ÷ 纯度） |
|---|---|---|---|
| 神通 | `1.808` 倍 | `1.500` 倍 | **`1.205`** ✅ 品级主导 |
| 修炼 | `1.808` 倍 | `1.500` 倍 | **`1.205`** ✅ 品级主导 |

> 这正是大人要的「**品级高的纯度低，也不比品级低的修炼速度慢多少**」—— 判据 `> 1` 即成立。

> ⚠️ **与世界观原表的关系（口径归属 · ADR-0019 ⑦）**：
> 世界观 `灵根资质品级.md` 品级表的「**神通倍率**」「**修炼速度**」两列，
> **在游戏数值侧由本节公式取代**；原表**保留为叙事口径**（排序完全一致，不构成冲突）。
> 世界观 `修为体系.md` 的「灵根纯度加成」（`+0%~+500%`，6 倍跨度）**已被裁定 N 弃用**
> （否则纯度会盖过品级）—— 原表仍在、**本仓不改**（铁律一：上游只读）。

### 6.3 战斗结算公式（**权威**）

> ★ **v0.4 两处改动**（ADR-0019 **③⑦**）：**术语**「会心」→「**暴击**」；
> **伤害式**由未定义的「纯度效率」改为 **§6.2 的「灵根增益」**（`G × c`，基准 `1.0`）。
> ⚠️ **不是改名，是语义换制** —— 原式 `(1 + 纯度效率)` 把「效率」当**增量**（`0` = 无加成）；
> 新口径的「增益」是**倍率**（`1.0` = 基准）。不显式改，两套语义会同时存在于同一份契约里。

```
命中判定: clamp((攻方命中 - 守方闪避) / 100, 5%, 95%)
暴击判定: clamp(攻方暴击率 - 守方暴击抗性, 2%, 60%)
格挡判定: clamp(守方格挡 - 攻方破防系数, 0%, 50%)

基础伤害（物理技能）：
  attack  = 物理攻击 × 攻方灵根增益
  defense = 物理防御 × (1 - 攻方破防%) × 守方灵根增益
  base    = max(1, attack - defense × 0.8)

★ 法术技能的**施放前置**（**ADR-0020** · 准入禁止）：
  施法者须拥有该法术的「**所需灵根**」（对应系灵根）—— 无则**不可学、不可放**。
  **以下法术式仅在该前置成立时适用**；「无属性」法术无此要求。

基础伤害（法术技能）：同上，物攻/物防 → 法攻/法防；
  且「攻方灵根增益」取**法术对应灵根**那条的纯度（**逐系** —— 裁定 L / §6.2）
  —— 因上述前置，「法术对应灵根」**必然存在**（**不再有空集分支**）

灵根增益 = 品级值 G × 纯度系数 c        （§6.2；基准 1.0）

最终伤害 = base
  × 技能倍率
  × 元素乘区：攻方对应系攻击加成 × (1 - 守方对应系抗性) × 生克倍率
  × 暴击乘区：命中暴击 ? 暴击伤害倍率（默认 1.5） : 1
  × 格挡乘区：触发格挡 ? (1 - 格挡减伤) : 1
  × 负面修正：心魔 → 法术 -5%~-15%；狂躁 → 暴击伤害 -10%；丹毒 → 全伤害 -5%
  × 随机浮动 0.9~1.1

跨阶修正：大阶差距 ≥ 2 时，元素生克倍率衰减 50%
```

> ⚠️ **本节 M1 不消费**（M1 无战斗）—— 口径先对齐，**公式实现与逐条核对归 M2**。

**生克规则**：五行相克 **±20%**；雷**破法 +15%**；冰克火 / 水 / 金。

### 6.4 平衡红线（原型踩坑记录，**契约级约束**）

| 项 | 上限 / 保底 |
|---|---|
| 破防 | **≤ 60%**（防御收益须保底，避免防御贬值） |
| 暴击率 | **封顶 60%**；暴击抗性与命中有下限保障 |
| 元素与基础攻击 | **分属不同乘区**，但总量控制（加法池 / 乘法池分离） |
| 三负面 | **不能只有惩罚** —— 须留双刃机制（如心魔 >70 时法术威力 +20% 但可能失控） |
