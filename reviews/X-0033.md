## 二、改动清单

### A. `gbe-studio`（v0.6.1）

- `core/policy/test/router.smoke.js`：
  - **unreal / godot 的 MCP 候选**：`assert.strictEqual(len, 3)` / `(len, 1)` → 改为 **逐 id 与 `mcp.json` 的实现表相等（含顺序）**。
  - **降级链**：硬编码 `['meshy','fal','hunyuan3d']` → 改为读 `fallback.json` 的 `chain`。该用例名字本就写着「读自 `fallback.json`」，**名字与做法不符**，正是漂移的温床。
  - **语义动作数 `8`**：**保留字面量、不派生**，并写明理由 —— 派生掉它 = 注册表擅自加第 9 个动作时没人报警。**契约要的是 tripwire，不是同步。** 另补一条真校验：每个有 `semantic_map.json` 的引擎，其动作集必须与注册表**完全相等**（少一个 = 未映射，多一个 = 私造）。
  - **新增注册表形状守卫**：每个实现必须**声明** `source` / `engine_version_range` / `maturity` —— **缺键非法，`null` / `unknown` 合法**（`CONVENTIONS §20.3`：`null` = 未核实；省键是逃过声明）。这条是派生化之后**必须补的账**：数量不再写死，内容层面的偷工减料就没人管了。
- ★ **派生化的代价写在明处**：本用例现在验**接线**不验内容 —— 塞一个字段齐全但不该存在的实现，它不报警（那属注册表内容审阅，另有归口）。

### B. `gbe-assets`（v0.5.2）

- `packages/schema/index.js`：版本闸门改为**只在 `schema.required` 含 `schema_version` 时**才套。
  实测对照：`kit` → 不再报「缺少 schema_version」，改报**真实原因**（三条 `$comment`）；
  `collection`（schema 要求该字段）→ 缺 `schema_version` 仍 `EXIT=1` 报原话 ⇒ **闸门没被拆掉，只是不再乱套**。
- `packages/schema/package.json`：`files` 补 `assembly.js`（`index.js:26` 就 `require` 它，此前 `npm pack` 产物发布即坏）。
  ⚠️ 只补崩溃，**不让本包能独立发布**：`REPO_ROOT` 指向包外两级的 `catalog/schema/`，`assembly.js` 还要读 `kits/` ⇒ 离开仓库跑不动。这是 `AGENTS.md` 纪律 3 的**既有设计**（开发期 `file:` 引用 / CI 期 submodule 锁 commit），不是漏洞；要真发布得先解耦，属另一张卡。
- `packages/schema/test/smoke.js`：原「正例：kit.json 通过」用的是**手工合成、刻意不含 `$comment`** 的夹具 —— 与真源分叉，正好把 A-1 掩盖掉。现**改名标明是合成夹具**，并**新增一条真源用例**直接把 `kits/cn-ancient/kit.json` 喂给 `validateKit`。

### C. `qiuyuan-guild`（四条假绿）

- **G-1** `check-doc-anchors.js` `hasSelfTestAndPending()`：`selfTest` 原来**不剥注释**（同一函数里 `pending` 却剥），一句注释就能被判「具备反向测试」。现改为**剥注释 ＋ 要求真有 `argv.includes('--self-test')` 分支**。
  - ★ 顺带把 `check-asset-ref.js` **真的补上了 `--self-test`**（13 用例），并把 A2 的正则抽成纯函数 `missingBaselineDeclarations` 以便被反向测试驱动 —— 否则判据修严只是多一条红，没有把缺的东西补上。
  - 补 4 条反向用例（行注释 / JSDoc / 只有字符串 / 真有 argv 分支）——**原来 `PENDING_RULES` 有注释绕过用例、`selfTest` 一个都没有，这个不对称就是假绿永远不被自己发现的原因**。
- **G-2** `check-data.js` `R4`：原判据 `if (!/unknown/.test(契约全文)) err else ok` —— 被 `data-contract.md:122` 那句**规则条文自己**喂饱，从上线起不可能红。现改为扫**真正的枚举取值表**（表行里 ≥2 个 `数字=值`），三条分支：识别不到 → err（禁止空集真空通过）；识别到但无一含未核实哨兵 → **err**；部分含 → warn 点名。补 8 条反向用例，含「**规则条文自身不得被当成落地证据**」那条。
- **G-3** `check-records.js` `declaresL3()`：原判据**全文**匹配「大人」⇒ 头部「发起方：大人」就能顶替审核节的终审声明。现改为**有审核节就只认节内**；无审核节时退回全文（那是 `C1` 的管辖，不在这里重复报，也不借此把存量卡一次性打红）。
- **G-4** `check-records.js` `sectionPresence().evidence`：原判据 `/验证证据/ || /门禁/` 全文命中 ⇒ 正文提一句「门禁」就算有证据节。现按**节标题**认（`验证证据` / `证据摘要` / `实测证据` / `门禁与自检` —— 后者是存量卡的既有合法形态，收紧判据不许顺手把合法形态判死）。
  ⚠️ **同一形状的漏洞在 `changes` / `review` 两条上还留着**：大人本次只点了 G-4，一并收紧会把与本次无关的存量卡一次性打红 ⇒ 登记为遗留 5，不夹带。
