## 二、修判据②·2：从"永远跳过"到"真做"

### 2.1 原来是什么样

```bash
if command -v node && [ -f "$ROOT/scripts/check-md-tables.js" ]; then
    node "$ROOT/scripts/check-md-tables.js" "$ROOT" || FAILED=1
else
    echo "    · 跳过（无 node 或未装 check-md-tables.js）"     # ← ★ 永远走这一支
fi
```

★★ 而那个 `.js` **从来不存在** ⇒ ★ 这条判据**永远打印"跳过"**。
★ 判据：★ **"跳过"长得像绿灯** —— ★ **一个永远跳过的判据，比没有判据更坏**（★ 它让人以为"表格有人管"）。

### 2.2 改成了什么

★ **用 awk 内联实现**（★ 顺带**去掉 node 依赖** —— 本仓其余检查都是 shell）：
★ 口径：**同一张表里每一行的 `|` 个数必须相同**（表头 / 分隔行 / 数据行**一起比**）——
★ 因为 `| a | b |` 与 `|---|---|` 与 `|:--|--:|` 的 `|` 数**都是 3** ⇒ 天然可比。

### 2.3 ★★ 写完当场踩的两个坑（★ 都进了 `--selftest`）

| # | 坑 | 后果 |
|---|---|---|
| ① | ★ 单元格内容里的**转义竖线 `\|`** 被当成了列分隔符 | ★★ **误报** —— 实测把本仓**两张好表**判成坏表（`references/02` 与 `05` 各一处） |
| ② | ★ 「首尾都有 `\|`」才算表格行 —— 非表格行要**结束当前表** | ★ 否则**跨表串号** |

⇒ 处置：`gsub(/\\\|/, "", t)` 先去掉转义竖线再数。
★★ ★ **两个坑各配一条反向用例**（★ 见下）—— ★ 只修不测 = 下次还会踩。

### 2.4 ★★ 反向用例：从 **3 条 → 5 条**

★ 新增两条，**一正一反**：

| 用例 | 断言 |
|---|---|
| **[D]** 塞入列数不一致的表 | ★ **必报**（`列数 3 != 表头 2`） |
| **[E]** 塞入**带转义竖线**的**好表** | ★★ **不得误报** |

★★ **为什么必须一正一反**：★ 只测"坏表被拦" ⇒ 判据**把表全判坏**也照样过；
★ 只测"好表通过" ⇒ 判据**永远报绿**也照样过。★ **两条一起，才证明它分得清好坏。**

★ 实测：`bash scripts/check.sh --selftest` → **五条全过**。

## 三、★ 顺带修 `sync-to-skill.sh` 的通配符坑（**第三次**）

★ 新增 `scripts/hooks/`（**目录**）后，旧写法**两头同时坏**：

| 头 | 坏在哪 |
|---|---|
| `cp "$SRC"/scripts/*`（**无 `-r`**） | ★ 对目录报错，而 `2>/dev/null` 把它**吞掉** |
| 计数 `ls -1 "$SRC"/scripts/*` | ★ 目录被**展开**、还多算一行表头 ⇒ ★ **数出 8**（实际 **5** 个文件） |

⇒ ★ 结果：报告「`scripts/ 5 个（源 8）` ⇒ **同步不完整**」—— ★★ **而真正坏的是计数本身**。

★ 处置：**拷与数都改用 `find … -maxdepth 1 -type f`** —— ★ **同源**，不再各自漂移。
★ 另：`hooks/` **本就不该同步给 skill**（★ 它是**仓的机制**，不是"给 Agent 看的内容"）。

### ★★ 三次同类的元教训（★ 第三次才写全）

★ ① 初版 `cp scripts/*.sh` ⇒ ★ 新增 `.py` 被**静默漏掉**（报告照样说"3 个"）
★ ② 改成 `cp scripts/*` ⇒ 解决 ①
★ ③ 加目录 ⇒ **拷贝与计数各坏一头**，且**互相指责**

> ★★ 定稿判据：**「拷什么」和「数什么」必须同源** ——
> ★ 否则它们会**各自漂移，然后互相指责**（这次的"同步不完整"就是这么来的）。

## 三·补 ★★ 同一处病灶：guild 自己的 `check-data.js` **R8** 也有

★★ **本轮最有价值的意外发现** —— ★ 提交本卡时，**guild 自己的门禁把推送拦下了**（★ hook 正常工作）：

```
✗ R8  reviews/X-0040.md:61 列数 4 ≠ 表头 3
✗ R8  reviews/X-0040.md:62 列数 4 ≠ 表头 3
```

★ 原因：★ 本卡 §2.3 那张表里写了「**转义竖线 `\|`**」这个说法本身 ⇒ ★ **被 R8 当成了列分隔符**。
★★ **与 ops 判据③ 是同一个缺陷** —— `lines[j].split('|').length - 2`（裸 split，没排除 `\|`）。

### 处置：**修判据**（首选路），不修数据

★ 新增纯函数 `tableCols(line)`：`line.replace(/\\\|/g, '').split('|').length - 2`，两处调用点同改。
★ **并加两条反向用例**（★ 一正一反，理由同 §2.4）：
- ★ 单元格含转义竖线的好表 ⇒ **不得误报**
- ★ **反向**：转义竖线**不能把真错掩盖** —— 列数真不齐仍必报

★ 实测：`check-data.js --self-test` → **64 / 64 全过**；`check-data.js` → **10 项通过 / 2 警告**（★ 2 警告是**存量** R4/R5，非本轮引入）。

### ★★ 沉淀：这条判据缺陷**一仓修、另一仓也该查**

> ★★ **「转义竖线 `\|`」是 Markdown 表格里写"一个字面竖线"的规范写法**（GitHub / Obsidian / markdown-it 都认）。
> ★★ **凡"数表格列数"的判据，必须先把它排除** —— ★ 否则就是「**判据过宽 → 误报**」，★ 而**误报率高 = 没门禁**。
> ★ 实测**两个仓各有一处**：`qiuyuan-guild/scripts/check-data.js` **R8** · `ue-ai-ops/scripts/check.sh` **判据③**。★ **两处都已修，且都补了反向用例。**
