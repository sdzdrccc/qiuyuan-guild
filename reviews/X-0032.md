## 四、缺陷清单（按仓 · 分级）

### A. `qiuyuan-guild`（规范中枢 + 9 门禁脚本）

#### G-1【严重 · 门禁假绿】`D4` 对 `check-asset-ref.js` 判「具备 `--self-test`」，实际它没有

- 判据真源：`docs/CONVENTIONS.md:425`「每个脚本都必须带两条：`--self-test`（反向测试）与 `PENDING_RULES`」。
- 缺陷代码：`scripts/check-doc-anchors.js:154`
  ```js
  function hasSelfTestAndPending(scriptText) {
    const t = String(scriptText);
    return {
      selfTest: /--self-test/.test(t),      // ← 只看**原始文本**，注释/字符串也算
      pending: t.split(/\r?\n/).some(l =>
        /const\s+PENDING_RULES\s*=/.test(l) && !/^\s*(\/\/|\*|\/\*)/.test(l)),  // ← 这条却**剥离注释**
    };
  }
  ```
  **同一函数内两条判据口径不一致**：`pending` 明确抵制「把登记位注释掉」的绕过，`selfTest` 却能被注释骗过。
- 实测（我亲自复跑，非探针转述）：
  ```bash
  grep -n -- "--self-test" scripts/check-asset-ref.js
  # 44:/** 纯函数：待实现规则的提示文本（空名单 → null，便于 --self-test） */   ← 全文件**仅此一处，是注释**
  node scripts/check-asset-ref.js --self-test     # 输出与常规完全相同（5 项通过）EXIT=0，**未跑任何反向用例**
  # 用 D4 的判定逻辑直接判该文件：
  #   D4 判定 selfTest = true  ← 只看原始文本
  #   剥离注释后还有 --self-test 吗 = false
  node scripts/check-doc-anchors.js | grep D4
  #   ✓ D4  6 个脚本均具备 `--self-test` 与 `PENDING_RULES`      ← **假绿**
  ```
- **加重证据（仓库自陈矛盾）**：`docs/CONVENTIONS.md:439` 白纸黑字写「`check-asset-ref.js` **仍待补**」—— 文件自己承认缺，而 D4 判它「具备」。
- **自测抓不到它**：`check-doc-anchors.js` 的 D4 反向用例（`:342-345`）只覆盖「完全没有 `--self-test`」与「`PENDING_RULES` 被注释掉」两种，**独缺「`--self-test` 只在注释里」**这条 —— 与 `pending` 的两条注释用例**不对称**，故这个假绿**永远不会被它自己发现**。
- 影响：`D4` 那句「6 个脚本都被反向测试验证过」是**无保证的断言**；任何人写一句注释即可过。
- 归属：**guild 内部修复**（`selfTest` 改为与 `pending` 同口径剥注释 + 要求真自测块；补 1 条反向用例）。**不需 ADR**（属门禁判据修正 · 铁律五：与门禁冲突先怀疑自己）。
