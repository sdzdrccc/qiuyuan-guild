## 一、为什么是这两条

来源是 dalu 一张**纯文档卡**的执行过程（改一行界面文案 → 要编译 → 要起编辑器实跑门禁）。★ 文档卡本身没产出 UE 知识，
★ 但**执行它的路径上撞了两件**，而且都是「**换个 UE 工程 / 换台机器照样成立**」的：

| # | 病 | 通用判据 |
|---|---|---|
| ① | 长耗时编译丢进"会被回收的后台 shell" ⇒ **僵死**，而任务通知报「completed · exit 0」 | ★ **看 `cl.exe` CPU 增量 ＋ 产物 mtime，不看通知与退出码**；★ 正解是脱离父壳启动后轮询日志 |
| ② | Windows 上 `python` 指向**商店别名桩** ⇒ **零输出 · 退出码 49**，被误读成"脚本坏了 / MCP 不通" | ★ 跑 `.py` 前先 `where python`；★ 抄仓内门禁脚本里那份**已验证的绝对路径** |

★ 两条都属 `AGENTS.md` §11.2 表的**第一行**（换工程还算数）⇒ **该进 `ue-ai-ops`，不该留在项目侧**；
★ 项目侧（dalu 那张卡）只留**指针**，★ 不双写 —— 依 §11.4-3「`ue-ai-ops` 有了一份，项目侧只留指针」。
