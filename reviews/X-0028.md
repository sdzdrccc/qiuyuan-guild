## 二、缺陷清单（★ 可复现证据）

### D-1（P1）`fresh` 分支不查豁免表

```bash
# 改前
$ node scripts/check-records.js | grep "无同批记录"
✗ C5  dalu：… → d9c5062 …    # 真缺
✗ C5  dalu：… → 5be5985 …    # ★ 已由 T-0028 补记
✗ C5  dalu：… → daa6763 …    # ★ 已由 T-0028 §追加登记
结果：不通过（6 错 / 0 警告）
```

★ **危害不是「多报几条」**，而是**两种性质相反的事实被压成了一种** ⇒
读门禁的人**无法分辨哪笔是真缺口** ⇒ ★ 这是「**未覆盖 → 静默**」的同族
（不是漏报，是**把「已查清」与「没查」渲染成同一个样子**）。

### D-2（P2）`err()` 输出变量误用

```bash
# 改前：6 行的前缀完全相同（都取到循环外的最后一个 label）
✗ C5  dalu：… → d9c5062 …
✗ C5  dalu：… → 5be9905 …
```

★ 只有末尾 `→ xxx` 是各笔自己的，**前缀是同一个** ⇒ 读起来像一笔。

★ **本轮不走 ②** —— 那 4 笔的记录**刚补上**，事实已可查，但**「同批」这个纪律的原始意图**（交付即产记录）
