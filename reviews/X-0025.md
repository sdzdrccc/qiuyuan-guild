### D3 · **P2** 密码下限：客户端按字符、服务端按字节，注释却写「与服务端一致」

```text
# 客户端 QYDLoginScreen.cpp:105-116
107: // ★ 下限与服务端一致（6）；上限按 72 字节……
110: if (Password.Len() < 6)          ← FString::Len() 数的是 TCHAR（字符）
114: const FTCHARToUTF8 Utf8Bytes(*Password);
115: return Utf8Bytes.Length() <= 72  ← 这里数的是字节（对）

# 服务端 server/internal/login/token.go:143-152
143: passwordMinLen = 6
148: if len(pw) < passwordMinLen      ← Go 的 len(string) 是字节
```

**分叉实例**：密码「密码」= 2 字符 / **6 字节** → 服务端 `6 < 6` 不成立 ⇒ **放行**；客户端 `2 < 6` ⇒ **拒绝**。
方向是**客户端更严**（不会出现「客户端放行、服务端拒绝」），**功能无碍**；但 **107 行的注释是假的**，且两端对同一规则给出两种行为 —— 与 D2 同类：**注释/记录与实现不符**。

### D4 · **P3** 密码超 72 字节时，提示仍是「密码至少 6 位。」

`QYDLoginScreen.cpp:131-134`（注册）与 `:155-158`（登录）：`PasswordLooksValid` 返回 false 的**两个不同原因**（过短 / 过长）共用一条文案；服务端对应文案是「密码过长（最多 72 字节 · bcrypt 上限）」。

### D5 · **P3** 客户端不发 `list_characters`，且未在「本次未覆盖」声明

```text
$ 全客户端 Send 调用
QYDCreateCharacterScreen.cpp:140  Send("create_character")

QYDLoginScreen.cpp:164            Send("login")
```

当前 `QYDPlayerController.cpp:159` 用 `login_ok.hasCharacter` 分流（**单角色制下功能等价**，且属性面板属波次 4），**但 T-0027 §六「本次未覆盖」没有这一条** —— 读者会以为流程已按 §7 落齐。
⇒ **不是实现错，是声明缺失**（与 `X-0018` §4「未覆盖必填」同一个病）。

### D6 · **P3** `QYD_LISTEN` 的形态：两方假设不同，写错时「脚本正常、服务端起不来」

| 消费方 | 对 `QYD_LISTEN` 的假设 | 写成 `8080`（无冒号）时 |
|---|---|---|
| 服务端 `main.go:149` | 直接 `ListenAndServe(v)` → **要 `:8080`** | ❌ 起不来 |
| `gm-*.bat` | 读到后 `set "P_SERVER=%P_SERVER::=%"` **剥冒号**（给 netstat 用） | ✅ 正常 |

**独立复算**（我自己另写一遍，非复跑 dalu 的说法）：

```text
$ go run listencheck.go
addr=":8080"      err=<nil>
addr="8080"       err=listen tcp: address 8080: missing port in address
addr="localhost:8080" err=<nil>
```

文档 `.env.example:21` 写的是 `# QYD_LISTEN=:8080`（**带冒号**）⇒ **照文档填是对的、没问题**。
风险在「照 bat 的默认值 `P_SERVER=8080` 的心智去填」→ 服务端启动即失败，而 bat 一切正常 ⇒ **故障表象指向错的地方**。
⇒ 建议 dalu 在 `main.go` 规范化（无冒号则补 `:`）。**登记为隐患，不计入不通过的主因**。
