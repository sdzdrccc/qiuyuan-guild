> 规则真源：`docs/REVIEW-PROCESS.md` **§9.1**（三档放哪）＋ **§10.5**（怎么命名）＋ `docs/DECISIONS.md` **`ADR-0032`**。
> 本文件只是把规则**摆成可照抄的形式**；**冲突时以真源为准**。

## 1. 三档 —— ★「两问一刀」，别按「来源是谁」猜

1. **这份文档是「判定正本」还是「源材料」？** → 正本 ⇒ ① 档；源材料 ⇒ 进第 2 问。
2. **源材料的作者，是不是「本仓派出去的」？** → 是 ⇒ ② 档；否（第三方工具 / 别家 agent）⇒ ③ 档。

| 档 | 位置 | 装什么 |
|---|---|---|
| **① 判定正本** | `reviews/X-00NN.md` | **一份**审阅的判定 —— 二值 ＋ 分层归属，**一号一卡一台账** |
| **② 内部源材料** | `reviews/work/<来源>-<对象>/` | **大人派出去的每个 agent 各出一份独立报告**，**原样收录**（供横向对比） |
| **③ 外部源材料** | `reviews/ext/<来源>-<对象>/` | **非本仓派出**的报告（第三方工具 / 别家 agent），**原样收录** |

★ **只按「谁派的」判，不按工具品牌判** —— 大人派出去的，**哪怕用的是别家产品**，也进 `work/`。
★ **横向对比靠「多份源材料 ＋ 一份正本」**：各 agent 的报告**并列存档**；
判定差异由**主 agent 在正本 `X-*` 的专节里对照列出**（先例：`X-0053` §六）。
★ **不揉成一份**（对比信息就没了），★ **也不给每份各开一个 `X-` 号**（台账会被灌水）。

## 2. 命名（★ 两条硬规则）

| 什么 | 规则 | 例 |
|---|---|---|
| 目录 | `<来源>-<对象>` —— **一来源 · 一对象 · 一目录** | `mimo-qiuyuan-dalu/` |
| 文件 | `PROJECT-REVIEW-<agent名>-<模型名>-<YYYY-MM-DD>.md` | `PROJECT-REVIEW-MiMoDesktop-MiMo-2026-10-19.md` |

★ **一个 agent 对多个对象 ⇒ 各建各的目录**（`<来源>-qiuyuan-dalu/`、`<来源>-gbe-studio/` …），
**不要**把多对象揉进一个 `-project-group/`。

## 3. 两档源材料的**公共硬约束**（不许违）

1. ★ **不许占用 `X-*` 编号** —— `X-00NN` 是 **guild 本仓正本**的编号位（与台账同号、一卡一行）。
   ⇒ 本区文件的 **H1 不得以 `X-` 开头**；编号由 guild 侧**汇编正本时**才给。
2. ★ **必须自报来源** —— 头部元信息写清 `来源` / `Agent 名称` / `大模型` / `审查时间` /
   `覆盖了什么 · 没覆盖什么`。**不得自称「guild 侧 review」**（那是本仓执行者的名分）。
3. ★ **只读** —— 不改任何被审对象；**删除类结论只出清单，不执行**；
   上游库（`虬渊大陆` / `gbe-studio` / `gbe-assets` / `ue-ai-ops`）**一律只读**。

## 4. 头部元信息骨架（照抄这段）

```markdown
# PROJECT-REVIEW-<agent名>-<模型名>-<YYYY-MM-DD>

- 来源：<agent / 工具名>            ← ★ 必填：写你是「本仓派出的」还是「外部」
- Agent 名称 / 大模型：
- 审查时间：
- 审查对象：
- 审查范围：本次覆盖了什么 · **没覆盖什么**（★ 必填，防读者误读为「全审了」）
- 硬约束确认：只读 ✓ 未改被审对象 ✓ 删除类只出清单 ✓
```
