## 1. 三档 ＋ 布局（★「两问一刀」，先分类再放）

1. **这份文档是「判定正本」还是「源材料」？** → 正本 ⇒ ① 档；源材料 ⇒ 进第 2 问。
2. **源材料的作者，是不是「本仓派出去的」？** → 是 ⇒ ② 档；否（第三方工具 / 别家 agent）⇒ ③ 档。

| 档 | 位置 | 装什么 |
|---|---|---|
| **① 判定正本** | `reviews/X-00NN.md` | **一份**审阅的判定 —— 二值 ＋ 分层归属，**一号一卡一台账** |
| **② 内部源材料** | `reviews/work/<agent>/` | **一个 agent 一个文件夹**；该 agent 的每份报告**平铺**在内 |
| **③ 外部源材料** | `reviews/ext/<来源>/` | **一个来源一个文件夹**；报告平铺在内 |

★ **只按「谁派的」判，不按工具品牌判** —— 大人派出去的，**哪怕用的是别家产品**，也进 `work/`。
★ **文件夹只按来源分，不按对象分** —— ★ **不许**再建 `work/<来源>-<对象>/` 这种目录；
★ **不许**在 `work/` / `ext/` 根下散放文件，★ **不许**在 agent 文件夹里再建子目录。
★ **一次审阅覆盖多个对象 ⇒ 一份文档**（每个对象一个 `## <对象>` 节）；
分对象各跑一次 ⇒ 同一文件夹里多份，文件名用 `-<对象>` 区分。
★ **横向对比靠「多份源材料 ＋ 一份正本」**：各 agent 的报告**并列存档**；
判定差异由**主 agent 在正本 `X-*` 的专节里对照列出**（先例：`X-0053` §六）。
★ **不揉成一份判定**，★ **也不给每份各开一个 `X-` 号**（台账会被灌水）。

## 2. 命名（★ 两条硬规则）

| 什么 | 规则 | 例 |
|---|---|---|
| 文件夹 | `<agent>/` —— **一来源 · 一文件夹** | `qoderdesktop/` |
| 文件 | `PROJECT-REVIEW-<agent名>-<模型名>-<YYYY-MM-DD>.md` | `PROJECT-REVIEW-QoderDesktop-Qoder-2026-10-27.md` |
| 同一 agent 同日多份 | 末尾加 `-<对象>` | `PROJECT-REVIEW-QoderDesktop-Qoder-2026-10-27-qiuyuan-dalu.md` |

## 3. 公共硬约束（不许违）

1. ★ **不许占用 `X-*` 编号** —— `X-00NN` 是 **guild 本仓正本**的编号位（与台账同号、一卡一行）。
   ⇒ 本区文件的 **H1 不得以 `X-` 开头**；编号由 guild 侧**汇编正本时**才给。
2. ★ **必须自报来源** —— 头部元信息写清 `来源` / `Agent 名称` / `大模型` / `审查时间` /
   `覆盖了什么 · 没覆盖什么`。**不得自称「guild 侧 review」**（那是本仓执行者的名分）。
3. ★ **只读** —— 不改任何被审对象；**删除类结论只出清单，不执行**；
   上游库（`虬渊大陆` / `gbe-studio` / `gbe-assets` / `ue-ai-ops`）**一律只读**。
4. ★★ **报告只读 —— 不动别人的**（`ADR-0038` · `REVIEW-PROCESS` §9.4）：
   - **未提交**：只有**作者本人**可改自己那份；**别人不动**。
   - **已发布（已入 Git）**：★ **任何人（含作者）不得改写 / 删除 / 改名** —— 它是「当时看到什么」的证据。
   - **要补正 / 复审**：★ **另写一份新报告**（新日期或序号），头部写明「补正 / 复审 `<旧报告路径>`」。
   - **汇编方**只读、只引用，★ **不搬运、不改写、不合并**源材料正文。
5. ★ **索引不归你** —— `reviews/INDEX.md` 由**主 agent / 脚本**重生成；被派出去的 agent
   **不得**跑 `gen-review-index.js --write`、不得手改索引。

## 4. 头部元信息骨架（照抄这段）

```markdown
# PROJECT-REVIEW-<agent名>-<模型名>-<YYYY-MM-DD>[-<对象>]

- 来源：<agent / 工具名>            ← ★ 必填：写你是「本仓派出的」还是「外部」
- Agent 名称 / 大模型：
- 审查时间：
- 审查对象：<一个或多个；多对象就逐行列出>
- 审查范围：本次覆盖了什么 · **没覆盖什么**（★ 必填，防读者误读为「全审了」）
- 硬约束确认：只读 ✓ 未改被审对象 ✓ 删除类只出清单 ✓ 不改他人报告 ✓
```

> 一份报告覆盖多个对象时，正文用 `## <对象>` 分节，每节各自给出判定与证据。
