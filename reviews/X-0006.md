## 起因

大人原话：

> 「**不是适配手机端，是提前做好准备**，把相关的东西**整理出来，放到手机端目录里**，手机端现在是什么方案开发，**做完 PC 后怎么变成安装包**」

**这句话前四个字是纠正我** —— 我上一轮（X-0005）把「预留手机端」处理成了「**判据 + 三条纪律**」，
**大人要的是「归置」** —— 东西**放在哪**、**整理出来**。

## 关键判断（四条）

### 一、我上轮的错：**把「预留」窄化成了「判据」**

X-0005 的产出是一张**做/不做两栏表**。判据**本身没错**，但**只答了一半**：

| 问题 | X-0005 答了吗 |
|---|---|
| 现在**动不动手** | ✅ 答了（判据） |
| 东西**放哪** | ❌ **没答** —— 表里写着「打包流水线：现在不做、**后建**」，**却没说后建在哪** |
| **怎么变成安装包** | ❌ **没答** —— 上游 §2.5 只有一句「`RunUAT BuildCookRun` 一键出包」，**无链路、无前置、无产物** |

> **一句话**：**判据 ≠ 归置。** 判据回答「现在做不做」，不回答「将来东西在哪」。
> 散着 = 将来找不到 = **等于没有**。

### 二、「做完 PC 后变成安装包」**不是再做一个手机版**

**UE 是单工程多平台** —— 同一份 `QiuyuanDalu.uproject`，**切 Target Platform 出不同包**。

> **代价不在代码，在资产与渲染。** 逻辑层共用；
> **要变的是**渲染管线特性（Lumen→烘焙 / Nanite→关 / BC→ASTC / Deferred→Forward…）与平台预算。
> **所以「提前准备」的实质是约束（资产预算），不是目录。**

方案 §3.2 原文**早已写过**「移动端是构建配置，不是新目录」—— 与本判断一致，本次只是**把它落实成归置方案**。

### 三、🔴 实测新事实：**Windows 出不了 iOS 包**，并更正上轮的误导

**本轮实测**：
- `Engine/Binaries/Win64/{Android,IOS}/` **有平台模块 dll**（`IOSTargetPlatform.dll` / `AndroidTargetPlatform.dll`…）；
- 但 `Engine/Platforms/{Android,IOS}/` 在 **Launcher 预编译版**里**只有 `Plugins/`**；
- **iOS 的实际编译与签名依赖 Xcode，Xcode 只在 macOS 上**。

**故 X-0005 表格第 6 行「Android + IOS 的 TargetPlatform 已随引擎安装 → **已就绪**」是错的** ——
**「模块在」≠「能出包」**：Android 还缺 SDK / NDK / JDK；**iOS 在 Windows 上物理出不了包**。

> **与 MSVC 那条同源**：**「装了」≠「能用」**（X-0005 立的纪律）。
> **这次是同一个坑换了个面**：上一轮栽在「装了 ≠ 能编译」，这一轮差点栽在「装了 ≠ 能出包」。

**影响面**：**不阻塞任何里程碑**，只影响商业化期「上不上 App Store」的决策 → 登记待裁。

### 四、方案 §3.2 有一条分叉要关

方案 §3.2 并列了两条路：

```
- 若移动端也由 UE5 打包 → 仍在 ue-client/ 内。移动端是构建配置，不是新目录。   ← ✅ 结论
- 若另用引擎做轻量手机版 → 并列 unity-client/ 或 mobile-client/              ← ❌ 此路已关
```

**上游 §4.1 已裁「原生 UE5 Mobile 为主 + 云串流兜底」** → 「另用引擎做手机版」**不在方案内**
（云串流属**服务端侧**，更不在客户端目录）。
**处理方式**：**保留原行 + 标注关闭**，不删历史（方案变更摘要「只追加」，纪律与 ADR 一致）。

### 五、顺带修掉一个**台账级缺陷**：`X-` 编号被两套东西共用

**发现方式**：建本记录前**先查号** —— 发现 `ledger` §二 已有 `X-0005` / `X-0006`（**上游订正需求**），
而 `records/X-0005.md`（UE 工程规格）与之**同号不同事**。

**根因**：`X-` 序列被两套**正文归属不同**的东西共用 ——
`records/X-*.md` 的正文在**本仓**；`ledger` §二的正文**永远在上游**（铁律一：**不代写上游内容**）。
**故它们本就不该共用一个编号空间。**

**处置（拆编号空间）**：

| 编号 | 含义 | 正文在哪 |
|---|---|---|
| **`X-<四位>`** | 本仓（guild）自身完成的变更 | **本仓** `records/X-*.md`（索引 ↔ 正文**同号对应**） |
| **`T-<四位>`** | dalu 工程实现任务 | `dalu/records/` |
| **`U-<四位>`** ← **本次新增** | **向上游提出的订正需求** | **上游**（本仓只持索引 + 验收结论） |

> `ledger` §二 的 `X-0003~X-0006` → **`U-0001~U-0004`**。
> **判据（可迁移）**：**编号空间按「正文落在哪个仓」切分，不按「谁发起」切分。**
> **正文同仓 → 可共用编号；正文异仓 → 必须分号**，否则索引与正文的一一对应立刻失效。

**同时抓出第二个洞**：`records/X-0003 ~ X-0006` **四篇正文一直没进 `ledger` 索引** ——
违反 `ledger` 自己写的「**有正文无索引 = 孤儿记录**」。
**规则立了，但从未被执行过**（与 X-0002 记录的「机制设计完整但一条没跑过」**同一个病**）。已补登。

> **主动认错**：撞号是**我上一轮埋的** —— 建 `records/X-0005.md` 时没先查 `ledger` 占用。
> 本轮**先查号**才逮到。**教训**：**编号是共享资源，写入前先查占用，与「改文档前先 grep 上游」同源。**

## 关键取舍

| 取舍 | 结论 | 理由 |
|---|---|---|
| **是否建第二个 UE 工程** | ❌ **不建** | 两工程 = **资产两套 = 双真源**（违反 ADR-0002 精神 + 上游 §4.5「同一套玩法逻辑双端共用」） |
| **`platforms/` 是否并入 `tools/`** | ❌ **不并** | `tools/` 按**类型**（都脚本），`platforms/` 按**域**（某平台专属）—— 与 `Content/`「按功能不按类型」同一原则；将来加主机平台为**平级新增**，不动现有结构 |
| **是否建 `platforms/desktop/`** | ❌ **不建** | PC 是**默认路径**，无专属产出物 —— **不留同构空目录**（方案 §3.2「不留空壳」） |
| **上游 §4.3 十项改造清单是否抄进 MOBILE-PLAN** | ❌ **不抄** | 它是「**做移动端时**」的执行依据，抄进来让范围膨胀。**只落打勾骨架** |
| **`build-*.bat` / `build-ios.sh` 是否现在写** | **占位** | 内容依赖包名 / 签名 / SDK 版本，**现在写就是编**。占位写明「未启用」比空目录清楚 |
| **iOS 走法是否现在定** | **登记待裁** | **不阻塞任何里程碑**，商业化期前裁定即可 |

X-0005 立的「MSVC `14.44.35207` 被禁 → M1 前须升级」，**于 v0.20 撤回**。

| 判据 | 值 | 结论 |
|---|---|---|
| ❌ 目录名 `VC/Tools/MSVC/` | `14.44.35207` | 误判为**禁用** |
| ✅ `cl.exe` 的 **`ProductVersion`** | **`14.44.35228`** | **合规** |

更新二进制，**目录名保持基线名 `14.44.35207` 不变**。
`cl.exe` 里 `FileVersion` = `19.44.35228.0`（内核），**`ProductVersion` = `14.44.35228.0`（工具集 —— UE 读这个）**。

**UE 源码依据**：`IsValidToolChainDirMSVC()` **先读 `FileVersionInfo` 的 Product 三字段，读不到才回退目录名**。

**影响**：
- **M1 硬前置只剩一条** —— `qiuyuan-dalu` 的 `git init` + Git LFS（MSVC 那条**解除**）；
