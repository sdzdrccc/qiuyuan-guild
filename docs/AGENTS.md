## 2. 三条铁律（跨库边界 · 绝对不可违反）

### 铁律一：上游三库一律只读

`虬渊大陆` / `gbe-studio` / `gbe-assets`（以及 Codex 原型）**一律只读**。

- 发现世界观缺口 → 开**跨库任务卡**（`X-*`），走 `qiuyuan-vault-iterate` 流程，**在彼仓改**。
- 需要新资产 → 开跨库任务卡，走 `gbe-procedural-pipeline`，**在 GBE 侧产**。
- **禁止**在本仓或 `qiuyuan-dalu` 里改上游库的文件。
- 上游各有自己的规范、校验、版本门禁 —— 绕过去就是破坏。

### 铁律二：原型只回契约层，不回 dalu

Codex 原型是**消耗品**（验证用），已验证的结论**单向回流契约层**。

- **判据**：若 `qiuyuan-dalu` 干活时需要读原型目录里**任何文件**，说明契约漏了东西 —— 补契约，不是开个后门去读。
- 原型的代码、场景、材质在 UE5 视角下**都会丢**，别在上面加投入。

### 铁律三：guild 只装「无处可归的东西」

> **判据：这件事的「产生方」是谁？产生方在哪，它就归哪。**
>
> ⚠️ 此处的「产生方」= **发起方**，**不是执行位置**。（此判据读错一次，已留痕于方案 §15.1。）

| 内容 | 产生方 | 归属 |
|---|---|---|
| 世界观设定 | 虬渊大陆 | 留虬渊大陆 |
| 生成能力（提示词 / 流水线 / 脚本） | gbe-studio | 留 gbe-studio |
| 资产实体与资产 schema | gbe-assets | 留 gbe-assets |
| 游戏实现（代码 / 场景 / UI） | qiuyuan-dalu | 留 qiuyuan-dalu |
| **跨库契约 / 跨库台账 / 统一术语 / 准入规范** | **没有产生方** | **归 guild** ← 本仓的独有价值 |

**禁止**把本仓做成「杂物间」：凡有明确归属的，一律留原地，本仓**只登记指针**。

## 3. 六条绝对纪律

> **编号 0 为本轮新增的第一设计原则，效力最高**；原 **1~5 条编号保持不变**（避免全文引用失效）。
> 若 1~5 条与本条冲突 —— **以第 0 条为准**。

0. **世界真实性优先**（**第一原则** · 效力高于本文件其余全部条文）
   **一切设计从「这个世界的逻辑」出发，不从「游戏该怎么做一个功能」出发。**
   开工前必答三问（写进任务卡）：
   - **① 世界观依据** —— 出处在哪一页？**答不出 → 先开上游任务卡（铁律一），或砍掉。**
   - **② 感知路径** —— 玩家怎么感觉到它？**只能靠面板数字 → 不合格。**
   - **③ 删除测试** —— 失去的是「一段体验」还是「一个功能」？**后者 → 它是为做功能而做的。**

   冲突时 **世界逻辑 > 玩法便利**；但 **可玩性不可牺牲**（可牺牲的只有**便利性**）。
   **完整判据**：方案 **§0.0** / **ADR-0009** / `CONVENTIONS.md` **§7.4 第 1 号人工检查点**。

1. **契约先于实现，顺序不可颠倒**
   ```
   改契约（先落 ADR） → 改实现 → 改测试 → 记录
   ```
   **反模式**：先写代码/先填表，回头「补一下契约」。补的契约会退化成文档，失去约束力。

2. **契约真源只在本仓 `contracts/`，禁止任何本地副本**
   `qiuyuan-dalu` 与原型**不建 `contracts/` 目录**。
   理由：留一个本地副本，就等于留了一条**「悄悄分叉」**的路。

3. **ADR 只追加**
   推翻旧裁决 = **新增**一条带 `supersedes: ADR-xxxx` 的 ADR。
   **历史条目一个字都不许改。**

4. **交付即产记录；`records` 必须与它描述的改动同仓**
   - 本仓发起的**跨库任务 / 契约变更** → `records/X-*.md`（**本仓**）
   - `qiuyuan-dalu` 的**实现任务** → `dalu/records/T-*.md`（**彼仓**）
   - **禁止**把 dalu 的实现记录搬进本仓（记录会与 git diff 脱钩，查账失效）
   - 记录须含**可复现的验证证据**（命令 + 实际输出），不是「已测试通过」

5. **推导类结论必须留「可复核」标记**
   - `§14` 台账里，**凡不是大人明确表态、由我推导得出的项，必须标注来源**。
   - 凡用抽象词（产生方 / 归属方 / 职责 / 唯一真源）做归属推导，**当场写清取哪一义**。
   - **自检句**：**「这个词有没有第二种读法？第二种读法下，结论会不会变？」**

## 4. 文档维护专属纪律（方案已犯过三次，代价很高）

| 陷阱 | 正确做法 |
|---|---|
| 裁决改了，引用它的章节没改 | **改完必须全文检索引用处**（§5 自检清单给了命令） |
| 只改 §14 表格，忘了下方汇总行 | §14 **两处都要改**（14.1 表格 + 14.2 汇总行） |
| 方案升版，README 没跟上 | 方案改完**顺手核对 README** |
| 改写历史版本摘要 | **只追加，不改写** |
| 推导结论混记为「大人裁决」 | 标注来源 —— 推导本就该被复核，混记会**无形禁止复核** |

> **三类错误，只有第一类能靠 grep 抓**：
>
> | 类型 | 例子 | grep 能抓？ |
> |---|---|---|
> | 引用未同步 | §3 把 `contracts/` 画在 dalu 内，与 §14 相反 | ✅ |
> | 事实未复核 | 断言「hub 无游戏类 skill」（实际有） | ❌ 须实查 |
> | **推导用词不严** | 「产生方」被读成「执行位置」 | ❌ 须自问 |

## 6. 遇到分歧时

1. 先查本仓 `docs/DECISIONS.md` —— 可能已经裁决过了
2. 再查上游 `gbe-assets/docs/DECISIONS.md` —— 可能有约定
3. 再查 `虬渊大陆` 对应页 —— 可能有设定依据
4. 都没有 —— **不要擅自定**，把**选项与权衡**摆出来问大人；得到答复后**落一条 ADR** 再动手

> **摆选项时的要求**：给**代价对比**，不给「都可以」。大人要的是判据，不是菜单。

## 7. 沟通约定

- 称用户为「**大人**」。
- **结论先行、短句、结构化、不寒暄**。
- 变更汇报用摘要式：「**保留 / 改名 / 已同步 / 未改动**」。
- **该指错就指错，包括指出自己的错**。发现前面判错了，**主动说明错误类型**（引用未同步 / 事实未复核 / 推导用词不严），比含糊带过更被认可。
- 空间关系（归属、架构、目录）优先出**图**，优于纯文字表格。
