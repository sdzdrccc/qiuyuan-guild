# ROADMAP.md —— 里程碑路线图

> **这份文档解决什么问题**：`10-MMO化` 已有 **14 模块 / 84 项功能**，那是**目标态全景**，不是**一期范围**。
> 本文件把 84 项排成**纵向薄切片序列** —— 每个里程碑只做一条**端到端能玩通的闭环**，做完一个再开下一个。
>
> **依据**：`DECISIONS.md` **ADR-0003**（大人裁决：从最基础的开始，完善后再细化下一个）。
> **来源标注**：本文件的**排序方案是我的推导**，依据是功能依赖关系。**标为待大人确认** —— 见 §7。
>
> **v0.19 变更**：§0 新增 **横向约束**栏（手机端归此，**不单独立里程碑** —— ADR-0011）；M1 In scope 第 0 项补 **`platforms/mobile/`**；§9 加 `MOBILE-PLAN.md`。

---

## 0. 六条排期原则（硬性）

> **第 0 条为第一设计原则**（ADR-0009 / 方案 §0.0），**效力高于其余五条**；**原 1~5 条编号保持不变**。

0. **世界真实性优先。** 里程碑的出口不只是「**能跑通**」，而是「**这一步让世界更可信**」。
   新玩法 / 新系统开工前必答三问（**世界观依据 / 感知路径 / 删除测试**）—— 见方案 §0.0 与 `CONVENTIONS.md` §7.4 第 1 号。
   > **判据**：里程碑做完，玩家是**做成了**一件事，而不是**点开了**一堆面板。

1. **纵向，不横向。** 每个里程碑必须**打通四段**：`世界观 → 契约 → 服务端 → 客户端`。
   ❌ 不这样做：「先把 21 个实体全设计完」／「先把服务端所有服务写完」。
2. **一条闭环 = 玩家能做成一件完整的事。**
   ✅ 「建号并看到自己的属性面板」／「走进世界并移动」。
   ❌ 「数据层完成了 80%」。
3. **范围闸门。** 每个里程碑列出 in / out of scope。**out 的项冻结**，不许顺手做。
   > 冻结不是「以后再说」，是**明确不做** —— 顺手做出来的东西没有验收标准。
4. **契约增量生长。** 只写当前里程碑涉及的实体，其余标「未定义（等 M<N>）」。**不许预先展开。**
5. **上游缺口不阻塞。** `10-MMO化` 的 34 项 ⚠️ / 12 项 ❌，**凡不影响当前里程碑 → 直接推迟**。
   > 否则永远开不了工 —— 上游永远补不完。

### 横向约束（**不单独立里程碑，贯穿全部 M**）

有些事**不属于某一个里程碑**，而是**每个里程碑都得守** —— 它们进「出口判据」，不占 In scope。
**手机端就在这一栏**（ADR-0011）：它**不是一个里程碑**，是一条**贯穿式约束**。

| 横向约束 | 守什么 | 起于 | 依据 |
|---|---|---|---|
| **世界真实性** | 三问必答；出口不只看「能跑通」 | M1 | ADR-0009（§0 第 0 条） |
| **输入抽象** | 玩法代码不读键码，一律走 Enhanced Input 的 `IA_*` / `IMC_*` | M1（建工程即启用） | ADR-0010 §五 |
| **契约不含物理映射** | 表名 / 前缀 / 索引 / 存储引擎不进契约 | M0 起 | ADR-0001 |
| **移动端资产预算** | 资产入库前过「本项目取值」表 | **M4**（首次资产入库） | **ADR-0011** / `MOBILE-PLAN.md` §3.1 |
| **保留无损源** | 贴图/模型留原始高精度文件（BC↔ASTC 要整套重压） | **M4** | ADR-0010 §五 |

> **手机端为何不进总表**：它现在**没有要排期的活**（ADR-0011 §六）——
> 现在要做的只有**两条约束**（资产预算 / 输入抽象），**不是一件可以排期的事**。
> 归置点与出包链路已定死（`platforms/mobile/` · `MOBILE-PLAN.md`），**需要时直接开工，不必重新决策**。

## 2. 【M1】建号 —— 详案（**下一步就做这个**）

### 目标

> **玩家能注册登录 → 创建角色（灵根觉醒 / 体质觉醒 / 四洲出身）→ 看到自己的属性面板。**

这一条走通，就验证了**整条架构链**：契约够不够用、协议能不能实现、服务端与客户端能不能只读契约干活、Luban 配表能不能跑。

### In scope（**做完这些就停**）

| # | 内容 | 对应 `MMO功能清单` |
|---|---|---|
| **0** | **建工程骨架**：UE 工程创建（规格见 **ADR-0010** / 施工图 `PROJECT-STRUCTURE.md`）+ `git init`/LFS + 目录落位（含 **`platforms/mobile/`** —— 见 **ADR-0011** / `MOBILE-PLAN.md` §5） | — |
| 1 | **账号**：注册 / 登录 / 登出（REST） | A-账号 |
| 2 | **角色创建**：命名、性别 | A-角色创建与捏人 |
| 3 | **灵根觉醒**：七大品级概率表 → 生成灵根组合 + 每根纯度 | A-灵根觉醒 |
| 4 | **体质觉醒**：四档概率 → 体质层级 + 名称 | A-体质觉醒 |
| 5 | **四洲出身**：给声望/资源/流派倾向（**不给属性倍率**） | A-四洲出身、B-凡人开局 |
| 6 | **属性派生**：凡人态 + 炼气一层的完整面板（一级 + 二级） | B-境界基础属性 |

| 8 | **配置表**：`RealmLevelConfig`（仅凡人 + 炼气 10 层）经 **Luban** 导出 | — |

### Out of scope（**冻结，本里程碑不做**）

- ❌ 战斗、技能、功法 → M2 / M6
- ❌ 背包、物品、装备 → M5
- ❌ 世界、场景、移动 → M4（**M1 只用一个空场景验证「能进图」**）
- ❌ 社交、任务、邮件、副本 → M7+
- ❌ 装备词条加成、宝石、强化
- ❌ 移动端适配
- ❌ 捏人的美术表现（**M1 用默认模型 + 参数占位**）

| 实体 | 状态 |
|---|---|
| `Account` | 新增展开 |
| `Role` | 新增展开（`realm_id` **`1~9`** / `layer` **`1~9`** —— ADR-0006 / ADR-0004 **已裁**） |
| `RoleRoot` | 新增展开 |

### 出口判据（**必须可复现，不是「跑通了」**）

> 依据 `AGENTS.md` §3 纪律 4：记录须含**命令 + 实际输出**。

1. **架构判据**：**双端只读 `contracts/` 即可实现，全程不碰原型目录** —— 即满足铁律二的判据。**这条是 M1 的核心验收项。**
2. **数据判据**：建角后，库内 `Role` / `RoleRoot` 记录数与建角请求一致（给 SQL 输出）。
3. **数值判据**：属性面板任取 3 项，与契约 §4 / §6 公式**手算结果一致**（给两侧数字）。
4. **健壮判据**：断线重连后角色数据不丢；重复建角被拒。
5. **门禁判据**：`node scripts/check-data.js` 通过，且**新增规则有反向测试**（`CONVENTIONS.md` §7.1）。
6. **世界真实性判据**（**第一原则 · §0 第 0 条 · ADR-0009**）：
   - 建角流程里每一项（灵根 / 体质 / 出身）都能回答「**在这个世界，它从何而来、由谁测定**」；
   - 属性面板**每一个数**都能追溯到**来源**（境界 + 层次 ／ 体质 ／ 资质 ／ 每根纯度 ／ 三负面），而非凭空给出；
   - **不得**出现「为了好看而填的占位数值」—— 占位值必须显式标注为占位。
   > **判据**：面板上每个数，玩家都能问出「**为什么是这个数**」并得到解释。
   > 做不到 → **世界被降级成了数值表**（§10 反模式「面板数字代替体验」）。

## 3. 【M2】首战 —— 概要

**目标**：能在场景里移动、放技能、打死一个目标、被打死后复活。

- **In**：移动（步行）· 灵力/身法双资源 · 伤害结算链 · 属性生克 · 暴击/格挡/破防 · 死亡与复活 · 技能栏（**仅通用基础法术 1~2 个**）· 一个假人/妖兽目标
- **Out**：完整世界 · 副本 · PVP · 功法系统 · BUFF/Debuff 完整体系 · 群战同屏
- **契约增量**：`SpellDef`（缩水版：仅通用法术）· 战斗公式（已有，逐条核对）
- **出口判据**：伤害数字与公式**手算一致**；越阶挑战胜率落进健康区间
- **对应功能**：C-战斗（12 项里的核心 6~8 项）

> **⚠️ 与 M4 的边界**：M2 的「场景」是**一块测试用平地**（占位方块即可）。
> 真实世界的加载、地形、传送、资源刷新归 **M4**。

## 4. 【M3】成长 —— 概要

**目标**：修为能攒、境界能突破、寿元在流逝、属性随境界真的变强。

- **In**：修为获取（先只做「挂机 + 主线」两途）· 突破判定 · 寿元 ticking · 境界提升 → 属性联动 · 修为条 UI
- **Out**：其余五条修为途径 · 天劫 · 残灵湮渊 · 体修
- **契约增量**：`RealmLifeConfig` · `RealmLevelConfig` 扩到全 9 境界
- **出口判据**：从炼气一层修到筑基初期，全程无手改数据；寿元按现实时间正确扣减
- **对应功能**：B-成长与境界（7 项）

---

## 5. 【M4】入世 —— 概要

**目标**：进入真实大世界，能跑能传送，能捡到东西。

- **In**：四洲一海地图结构（**先只做 1 个洲的 1 个小镇**）· 移动五途（步行 + 1 种）· 场景加载（**接 GBE 资产**）· 传送 · 资源刷新 · 掉落物 `WorldDrop`
- **Out**：其余三洲 · 天候节气 · 迷雾探图 · 洞府
- **契约增量**：`WorldDrop` · `resource-manifest.yaml` 场景清单（与 `asset-ref-contract.md` 联动）
- **出口判据**：**删掉场景文件，能从 manifest 重新生成**（`CONVENTIONS.md` §4.3 判据）
- **对应功能**：L-开放世界（9 项）
- **⚠️ 强依赖 GBE 资产就绪** —— 这是全项目**最大瓶颈**，M4 是否如期取决于资产线

---

## 6. 【M5】背包 —— 概要

**目标**：捡到的东西能进背包，能穿上，属性面板跟着变。

- **In**：`ItemDef`（先只做装备 + 消耗品两类）· 背包格 · 装备 5 槽 · 强化（1 条线）· 词条加成合并
- **Out**：其余物品类别 · 宝石 · 洗练 · 传承 · 套装 · 摆摊
- **契约增量**：`ItemDef` / `RoleItem` + 词条 schema（**硬约束**：词条键名与面板键名逐字相同，§7.2）
- **出口判据**：穿上装备后，面板数值 = 派生值 + 词条加成，**脚本比对通过**
- **对应功能**：E-装备与法器（6 项）+ F 部分
